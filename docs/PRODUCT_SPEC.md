# Lerniqa｜學睿卡 產品需求規格 v0.2

## 目標
國小至國中學生的個人化練習系統；家長可整理教材、追蹤錯題與考前複習。首版以繁體中文、台灣學制為主。

## 核心角色
- 家長：建立學習者檔案、設定年級／科目／段考範圍、匯入題目、查看學習進度。
- 學習者：練習、檢視解析、重做錯題及建立自己的練習計畫。
- 家教：建立自己的題庫，並針對已分享給自己的學習者建立練習計畫。
- 審核者：檢查學習者答案與手寫內容。審核者可設定為家長、家教或後續新增的自訂身份。
- 管理員：管理教材與題庫品質（後續）。

## 核心流程
1. 登入帳號，建立或選擇學習者，並在獨立設定頁管理稱呼、年級、學期與練習偏好。
2. 建立考試設定：可新增多筆考試，分別保存名稱、日期與各科目的開始及結束範圍，並指定目前練習套用的考試。
3. 切換至指定學習者後，拍照或上傳圖片、PDF；系統先帶入該學習者目前設定的年級，再由後端 OCR 擷取題幹與選項，最後交由使用者校正。
4. 題目結構化：科目、年級、版本、冊次、單元、知識點、難度、正解、解析、來源。
5. 指派練習；記錄作答日、答案、正確率與耗時。
6. 錯題自動入庫，按知識點聚合；支援重做、熟練度追蹤。
7. 依錯題知識點找出相似題；AI 出題前要做答案驗證與人工可審核流程。
8. 考前儀表板：弱點分布、單元完成率、最近練習與考試倒數。

## 介面與操作原則

- 操作動線必須簡單，完成主要任務時只要求必要步驟，不讓使用者在多個頁面之間反覆切換。
- 每個畫面只呈現當下任務需要的內容與主要操作，避免同時放入過多功能入口。
- 相關資訊與設定應合併在同一區塊，不使用大量卡片、面板或重複標題切碎內容。
- 進階設定與低頻功能預設收合，需要時再展開。
- 學習者設定使用可擴充的獨立頁面，不使用彈跳視窗。
- 科目選項依目前年級的題目資料產生，只顯示該年級已有題目的科目。
- 書籍版本依科目分開設定，科目選項只顯示科目名稱。「全部科目」在選項中縮寫為「全部」。練習預設沿用學習者設定的版本；選擇單一科目後，可在進階設定暫時切換版本，且不修改學習者設定。選擇全部時，各科分別沿用自己的學習者版本。
- 每位學習者的每輪預設題數為 10 題；介面提供 5、10、15 題快速選項，也可輸入任意大於 0 的整數。複習計畫可臨時調整本輪題數，且不覆寫學習者預設值；若目前範圍題目不足，實際練習使用全部可用題目並明確提示數量。
- 總覽、練習設定、題庫匯入、錯題、成果與學習者設定各自使用固定網址；重新整理、上一頁與下一頁後仍需回到網址對應的頁面。
- 進行中的專注練習使用獨立網址。前端示範版重新整理該網址時回到練習設定頁，不宣稱已保存尚未送出的手寫內容。
- 畫面需有明確的主要按鈕；次要操作不得與主要操作使用相同的視覺層級。
- 新增功能時應優先整合進既有流程。若需要增加新的頁面或區塊，必須說明現有畫面為何無法容納。

## 帳號與登入

- 系統必須提供帳號登入；同一帳號可建立及管理多位學習者。
- 每位學習者的題目、練習計畫、作答紀錄、錯題與學習成果必須分開保存。切換學習者時，不得混入其他學習者的資料。
- 帳號可使用 LINE、Facebook 或 Google 綁定登入，也可使用電子郵件與密碼註冊及登入。
- 同一帳號使用多種登入方式時，登入身份需指向同一份帳號資料，避免產生重複帳號與分散紀錄。
- 登入、註冊、登出確認、忘記密碼、快速註冊與帳號綁定需使用獨立網址，重新整理後仍維持目前流程。前端示範版只呈現操作介面，不送出帳號資料，也不宣稱已完成 OAuth 或帳號綁定。

## 系統管理員

- 系統提供一個不寫入應用程式資料庫的預設系統管理員。其身分與驗證資料保存在後端部署環境的 Secret Manager（密鑰管理服務），不得放入 Vercel 前端、原始碼、fixture 或可由瀏覽器讀取的環境變數。
- 只有系統管理員可以授予或移除其他資料庫帳號的系統管理員權限。預設系統管理員不出現在一般帳號清單，也不能由管理介面修改或刪除。
- 一般帳號可以修改自己建立或匯入的題目與答案，不得修改其他帳號或系統提供的題目。系統題目只有系統管理員可以修改。
- 每一次管理員權限異動與系統題目修改都要由後端重新檢查登入身分及權限，並留下不可由一般管理介面修改的稽核紀錄。
- 完整資料契約、安全邊界與施工順序定義於[系統管理員與題目異動規劃](system-admin-plan.md)。

## 學習者共享與權限

- 學習者可分享給其他帳號，例如另一位家長或家教，不需複製學習者檔案。
- 所有取得分享權限的帳號，都能查看該學習者的練習計畫與學習成果。
- 學習者資料仍維持單一紀錄來源；不同帳號查看的是同一份資料，不得各自產生互不一致的副本。
- 學習者未分享給某個帳號時，該帳號不得查看其個人資料、計畫、作答紀錄或學習成果。
- 帳號可在家長、學習者與家教角色間切換。切換至家長或家教時需輸入六位數角色密碼；學習者角色不要求密碼。
- 切換角色時保留目前選取的學習者，不因角色改變而自動切換學習者。帳號設定需列出每個角色可以管理的學習者；角色未取得目前學習者的權限時，不得切換後存取其資料。
- 忘記角色密碼時，必須先以帳號的註冊信箱完成驗證，才能設定新的六位數角色密碼。前端示範版只模擬驗證流程，不宣稱已寄送真實郵件。
- 學習者可執行家長或家教建立的練習計畫，但不得修改其科目、範圍、作答方式、題數或進階篩選條件。

## 題庫與練習計畫

- 家教可在自己的帳號下建立與管理題庫。
- 左側導覽提供獨立的「題目總覽」。總覽可依關鍵字、科目、版本、單元、題型、來源、收藏清單及作答狀態篩選，並以分頁清單顯示結果；點選題目後，右側顯示完整題目、選項、答案、解析、分類與來源。
- 作答狀態至少包含全部、未做過、做過及最近一次答錯。同一題有多次作答時，以目前學習者最新一筆作答判定；待人工檢視仍屬於做過，但不算答對或答錯。
- 題目總覽與練習篩選應共用相同的作答狀態與相近題篩選規則，避免兩個入口對同一批題目產生不同結果。
- 收藏清單依學習者分開保存，且可建立多份。題目可同時加入多份收藏；「移動收藏」會先從其他收藏清單移除，再加入目標清單。
- 題目總覽的批次範圍可選「已勾選」或「全部篩選結果」。批次動作支援加入收藏、移動收藏與建立練習計畫；建立計畫時需固定當下題目清單，避免後續變更篩選條件影響已建立的內容。
- 家長、學習者與家教都可建立自己的匯入本。匯入本記錄建立角色及適用學習者；沒有選擇匯入本的題目歸入「系統預設」。匯入紀錄需顯示當次寫入的題本名稱。
- 家教可使用自己的題庫，為已分享給自己的學習者建立練習計畫。
- 學習者可建立自己的練習計畫。
- 每份練習計畫必須記錄建立者與適用的學習者，並與該學習者的作答紀錄及成果連結。
- 取得該學習者分享權限的帳號，都能查看其練習計畫與執行成果，不論計畫由家長、家教或學習者建立。
- 練習入口需在標題右側顯示目前學習者的連續練習天數；天數依臺北日期從作答紀錄計算，同一天多次作答只計一天，今天尚未作答但昨天有紀錄時保留既有連續天數。
- 建立練習企劃時，「練習篩選」包含科目、依章節／單元或依考試安排的範圍，以及收合的進階設定；答案檢核方式另列為「練習方式」。學校等學習者基本資料只在學習者設定維護，不在單次練習重複輸入。
- 練習篩選中的進階設定預設收合，展開後可設定難易度占比、題目來源、題型、知識點、作答狀態、相近題範圍、計畫建立者與本輪題數。來源可複選；來源、題型、知識點或作答狀態未指定時，代表使用目前科目與範圍內的全部題目。
- 練習設定需依目前選取的科目、章節或考試範圍及進階篩選條件，顯示總題數、已練習題數、完成百分比與已檢核正確率。同一題作答多次時只採用最新一次紀錄；待人工檢視的作答不計入正確率。
- 難易度分為易、中、難，三者占比合計必須為 100%；正式出題需依比例抽題。前端示範版只保存與驗證設定，不宣稱已完成 AI 抽題。

## 題目匯入與年級

- 使用者切換至某位學習者後，拍照或上傳的考題應自動帶入該學習者目前設定的年級，不必再次選擇。
- 自動帶入的年級必須寫入題目資料，作為後續分類、出題與搜尋相近題目的依據。
- 使用者可在題目校正時修改自動帶入的年級。
- 學習者尚未設定年級時，匯入流程需改由使用者手動選擇年級後才能繼續。
- AI 拆分完成後必須依原始順序列出所有題目與參考答案，不得只顯示第一題或抽樣結果；使用者確認全部題目後才能寫入題庫。
- 每一題可分別設定科目、書籍版本、單元、主題、難易度與來源。單元記錄題目在教材中的位置，例如第幾章、第幾課或 Unit；主題記錄跨書籍版本共用的學習內容，例如分數加法或近義詞。同一個主題可出現在不同版本及不同單元。
- 版本、單元、主題與來源均可選擇既有項目。每個選單的最後一項提供新增入口，選取後可直接輸入新項目。
- 科目、版本、單元、主題、難易度與來源均為選填；留白時由 AI 依題目與檔案內容提出建議，使用者確認前不得直接寫入。
- 匯入來源支援圖片、PDF 與直接貼上文字。來源中包含多題時，必須列出全部題目，不得只顯示第一頁或第一題。
- 上傳檔案與貼上文字使用同一個匯入區塊的分頁切換。檔案頁需支援拖放與點選檔案，並在寫入前顯示目前選擇的檔案。
- 題目中的圖片、數學圖形與題幹需保持關聯並依原始順序編排；校正時可替換、移除或重新指派附圖，避免 AI 拆題後圖片配對錯誤。
- 來源文件中每題附帶的欄位都必須保存，例如題目編號、難易度、出處、認知向度、知識向度與課名。系統不得只取目前畫面用到的欄位後捨棄其他內容。
- 文件欄位需同時保存原始標籤、原始值、標準鍵值、可篩選值、判定來源與信心值。新增欄位後，題庫查詢與練習進階設定應能依資料自動產生篩選選項，不需新增固定程式分支。
- 來源類型需支援舊綱題、會考、同步練習卷、基測、素養題、一般試題及後續新增類型。若文件提供年份、學年度或梯次，需分欄保存並可複選篩選。

## 題目與手寫作答

- 選擇題與是非題可使用既有的選項式作答介面。
- 題目必須保留來源文件的原始題幹、選項、答案、解析、題型名稱與順序，不可為了配合介面改寫成另一道示範題。
- 寫出國字與注音、注釋、改錯及填充等書寫題不得建立選項。配合題、選詞測驗與題組需保存每一個小題及其選項，作答時逐小題收集答案。
- 每一題都必須在題目旁提供大型手寫板，讓學習者保留計算過程或直接寫下答案。
- 練習時使用專注版面，不顯示工作區側欄、摘要或其他功能區塊；桌面版為左側題目、右側手寫板，窄螢幕改為上下排列。
- 練習右上角提供關閉入口，學習者可暫時關閉並保留目前進度，或結束練習並捨棄尚未送出的本題內容。
- 練習畫面不提供鍵盤計算筆記；書寫題可保留文字答案欄位，作為尚未串接手寫辨識時的替代輸入。
- 手寫內容必須跟隨該題答案保存，並可在答案審核與歷史作答中重現。
- 手寫板提供畫筆、橡皮擦與清除功能；說明文字與工具列集中在標題區，避免壓縮可書寫空間。
- 練習結果有手寫內容時，桌面版在題目右側顯示原始手寫；沒有手寫時，題目內容使用完整寬度。
- 中文國字題可個別設定是否啟用 AI 手寫辨識與答案驗證。介面階段只標示尚未連接，不產生模擬辨識結果；正式串接後的辨識結果只能作為輔助判斷，不可覆蓋原始手寫內容，也不可在未經確認時視為正確答案。

## 作答與檢核模式

開始練習前可選擇下列模式：

- 全部作答後檢核：學習者完成整份練習後，再一次檢查答案。
- 逐題檢核：每完成一題就檢查答案，適合由家教或家長陪同練習。
- 只顯示成績：完成整份練習後只顯示分數、答錯題數與待檢視題數，不顯示個別答案、參考答案或解析。

逐題檢核時，系統應在檢核完成後顯示下一題。全部作答後檢核時，結果頁需提供「練習相近題目」動作，讓學習者選擇是否加入相近題型再次練習。

## 答案審核

- 檢視答案時，可切換至審核者身份。審核者身份需可定義，首批支援家長與家教。
- 審核畫面可設定是否同時顯示參考答案與學習者手寫內容，預設為顯示，以便直接比對。
- 關閉答案比對時，審核者仍可查看學習者原始作答，但參考答案不應出現在同一畫面。
- AI 手寫辨識結果需與學習者原始手寫內容分開呈現，讓審核者能修正判定。

## 錯題與相近題

- 學習成果中的每次練習明細提供「全部題目」與「錯題」分頁，預設顯示錯題；全部題目需保留每題原始題號及作答結果。
- 每道錯題提供「立即測驗」與「相關題目練習」。立即測驗只重做原題，題組中的小題也不得自動擴成整組；相關題目優先使用已建立的相近題，沒有明確關聯時依同年級的主題、知識點、單元與科目依序選題。兩種練習完成後都需依練習用途新增至練習紀錄。
- 歷史錯題可個別勾選是否產生相近題目，作為再次考核內容。
- 每道歷史錯題需顯示其相近題目的累計結果：已完成題數、答對題數與答錯題數。
- 相近題必須能追溯至原始錯題與知識點，避免同一題在不同錯題紀錄中重複計算。
- 產生相近題目後，學習者可選擇立即練習或加入後續練習。
- 題目總覽與練習篩選需提供「錯題與相近題」範圍。選取後列出目前學習者最近一次仍答錯的題目，以及與這些錯題已有明確關聯的相近題。沒有相近關聯的錯題仍需保留在結果中。
- 相近題不能只因科目、單元、知識點或題型相同就視為同一類。只有資料庫中已建立並確認的相近關聯，才可用於篩選與排除；關聯判定方法與審核規則另行制定。
- 相近題篩選需提供「排除已掌握題組」選項。對同一位學習者，同一相近題組中至少有兩個不同題目的最新已檢核作答為答對時，開啟此選項後排除該題組的所有題目。相同題目重複答對只算一題，待人工檢視不列入計算。
- 是否排除只影響當次查詢與出題結果，不得刪除題目、相近關聯或歷史作答。沒有相近關聯、關聯尚未確認，或群組內少於兩個不同題目答對時，不得套用排除規則。

## 重要資料模型
User, AccountIdentity, Student, StudentAccess, ReviewerRole, Subject, CurriculumUnit, ExamPlan, PracticePlan, QuestionBank, SourceDocument, Question, QuestionRevision, QuestionChoice, QuestionTag, QuestionSimilarityGroup, QuestionSimilarityMembership, PracticeSession, AnswerAttempt, HandwritingAnswer, MistakeReview, GeneratedQuestion, AdminAuditLog。

關聯要求：一個帳號可關聯多位學習者，一位學習者也可授權給多個帳號；登入方式需關聯至同一帳號；題庫與帳號建立的題目需記錄擁有者；系統題目需有明確來源標記；練習計畫需記錄建立者與學習者；題目能追溯原始檔案及頁碼；學習者作答有時間戳並連結當時的題目版本；更正題目、答案或解析不得覆寫歷史作答的判定依據；手寫答案需連結到題目與作答紀錄；相近題需連結到原始錯題；管理員權限異動與系統題目修改需留下稽核紀錄。

`QuestionSimilarityGroup` 代表一組經分析後認定為相近的題目，至少保存群組識別碼、狀態、建立來源、判定方法版本及建立時間。`QuestionSimilarityMembership` 保存題目與群組的多對多關聯，至少包含群組識別碼、題目識別碼、關聯狀態、判定依據、信心值及審核資訊。同一題可依後續規則加入多個群組；查詢時只使用已確認的關聯，關聯異動不得改寫既有作答紀錄。

## 品質／隱私
- 未成年者資料預設不公開；採最少蒐集。
- OCR 與生成結果不可默默當作已驗證正確答案。
- 影像/PDF 上傳需檔案大小、型態、權限驗證及惡意內容掃描。
- 文件可能涉及教科書著作權：僅允許使用者有權使用的教材，分享功能另設限制。
- 需依臺灣個資法與適用兒少規範設計權限、資料刪除與保存期限。
- 每次讀取或修改學習者資料時，都必須依帳號與學習者的分享關係檢查權限，不可只依前端目前選取的學習者判斷。

## MVP 範圍
可操作介面、示範題目練習、錯題紀錄、篩選、練習日期，以及由模擬 API 寫入本機 JSON 的資料流程。初始資料由 repository 內的 fixture 提供，新增與修改資料寫入不進版控的 runtime JSON。正式帳號、雲端資料庫、真 OCR、AI 出題與 AI 手寫辨識均列入下一階段。

相近題關聯目前只保留產品與資料模型規格。正式資料庫、關聯分析與審核流程完成前，不在前端用科目或題目標籤模擬關聯，也不顯示會讓使用者誤以為關聯已建立的篩選結果。

## 模擬 API 與 JSON 資料契約

- 前端不得直接引用題目與學習者 fixture；所有可操作資料都經由 `/api/v1` 讀寫。
- `data/fixtures` 保存可重設的初始資料。本機開發將實際寫入結果存入 `runtime-data`；Vercel 將結果存入該執行個體的暫存目錄。兩者都不進版控，Vercel 暫存資料可能在重新部署或執行個體更換後重設，不得當成正式持久資料庫。
- 題目必須保存科目、年級、學期、版本、章節或課次、單元、主題、知識點、題型、難易度與來源。來源需保留原始檔名、頁碼或題號，以及資料來自文件、路徑、AI 或人工確認。未列入固定欄位的文件項目保存於 `metadata`，不可在匯入時捨棄。
- `kind` 只描述作答方式；`typeLabel` 保存來源文件的題型名稱，`sourceAnswer` 保存來源文件原樣的答案文字。複合題以 `parts` 保存每一個小題、選項與答案，避免把整組題目壓成單一選擇題。
- 題幹、選項、答案與解析採有序內容區塊。圖片本體存入 runtime asset 目錄，JSON 保存檔案鍵值、MIME type、替代文字、尺寸、所屬區域與顯示順序。
- 題目匯入確認會實際新增 JSON 題目與匯入批次；OCR 與 AI 拆題仍使用模擬結果，介面必須清楚區分兩者。
- 未來改用資料庫時保留 API 路徑與回應格式，只替換資料存取層。

## 待確認事項

- 分享帳號除了查看學習成果與計畫外，是否能修改或刪除其他人建立的計畫。
- 學習者分享是否區分家長、家教與唯讀等權限，以及誰可以邀請新帳號或撤銷分享。
- 家教題庫是否能分享給其他帳號，或只能由建立題庫的家教使用。
- 「全部作答後檢核」是否也要在每道錯題旁提供「練習相近題目」，或只在整份結果頁提供一次統一入口。
- 審核者的自訂身份只需要顯示名稱，還是需要各自設定可檢視、批改與修改答案的權限。
- 數學題手寫板要只保存圖片，還是也要辨識算式並支援逐步檢查。首版未納入算式辨識。
