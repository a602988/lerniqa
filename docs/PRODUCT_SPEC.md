# Lerniqa｜學睿卡 產品需求規格 v0.2

正式匯入的題目、帳號、角色、學習者、練習與作答紀錄屬持久資料，不得用 seed、reset、fixture 還原或測試 cleanup 覆蓋。合成 fixture 只用於明確隔離的測試資料庫；資料量少不會改變持久資料的性質。

信箱驗證、密碼重設與角色 PIN 設定／重設的 API、介面與不連網針對性測試已完成，token 只保存 SHA-256 雜湊。`0012` 已將 challenge 固定綁定到電子郵件 identity；SMTP outbox 不在 `0012`。ERP 現行 SMTP 的非機密 host、port 與 TLS 模式已核實；Lerniqa 自己的憑證、outbox、實際 handshake、測試收件人與真實投遞仍未設定，也不得讀取或複製 ERP secret。目前同步寄信仍可能讓已知與未知帳號產生 timing enumeration，outbox／等時回應是獨立的上線阻擋。成人角色切換仍使用帳號密碼重新確認，角色 PIN 尚不參與角色切換。圖片與 PDF 會先完成校正、去除彩色手寫與 OCR，再由固定本機 Ollama vision model(圖片理解模型)逐頁建立多題候選；候選必須通過既有交換格式與題目草稿契約，使用者校對後才可加入題庫。本地 AI 手寫分析已接上 `0012` sidecar 與固定 Ollama 模型；模型只產生待審建議，不直接改判。

## 免費方案額度

一般註冊帳號預設使用免費方案。每個帳號可保留最多 100 題非封存的自建題目；封存題目後會釋出額度。帳號下所有學習者與練習模式共用每日 10 題的成功作答額度，日界依 `Asia/Taipei` 00:00 計算。相同 idempotency key（冪等識別碼）的重送不重複計量；第 11 題由伺服器拒絕，既有練習進度維持不變。固定授權帳號透過 `account_plan_assignments` 指派其他方案，不得寫死於前端。

## 目標
Lerniqa 是持續開發中的多科目正式產品，提供國小至高中學生個人化練習；家長可整理教材、追蹤錯題與考前複習。首版以繁體中文、台灣學制為主。各功能按交付狀態說明，不另建單一科目首頁或替代產品流程。

## 帳號密碼交付狀態

帳號註冊與密碼重設的新密碼至少 8 個字元，不要求大小寫、數字與符號混用，並拒絕常見弱密碼、全空白及首尾空白。前後端使用共同驗證規則，既有密碼不批次修改，登入保留相容。密碼重設的 API、介面與郵件 adapter 已通過不連網針對性測試；它不會改動電子郵件的 `verified_at`，成功後撤銷該帳號的所有 session。`0012` 的 identity binding 已整合並通過 migration 驗證；SMTP outbox／等時回應、Lerniqa 憑證、handshake 與真實寄送另列為未完成，因此尚不是 production 帳號復原流程。

## 核心角色
- 家長：建立學習者檔案、設定年級／科目／段考範圍、匯入題目、查看學習進度。
- 學習者：練習、檢視解析、重做錯題及建立自己的練習計畫。
- 家教：建立自己的題庫，並針對已分享給自己的學習者建立練習計畫。
- 審核者：檢查學習者答案與手寫內容。審核者可設定為家長、家教或後續新增的自訂身份。
- 管理員：管理教材與題庫品質（後續）。

## 核心流程
1. 登入帳號，在「系統設定」查看帳號身分並建立或選擇學習者；建立學習者時先選學生或社會人士。學生再依教育階段選年級與學期，社會人士不保存年級與學期。切換到學習者後，再到「學習者設定」管理稱呼、就學資料與練習偏好。
2. 建立考試設定：可新增多筆考試，分別保存名稱、日期與各科目的開始及結束範圍，並指定目前練習套用的考試。
3. 切換至指定學習者後，拍照或上傳圖片、PDF 與受支援的文件；系統先帶入該學習者目前設定的年級，再擷取題幹與選項，最後交由使用者校正。來源缺少標準答案時，不得自動補造答案。
4. 題目結構化：科目、年級、版本、冊次、單元、知識點、難度、正解、解析、來源。
5. 指派練習；記錄作答日、答案、正確率與耗時。
6. 錯題自動入庫，按知識點聚合；支援重做、熟練度追蹤。
7. 依錯題知識點找出相似題；AI 出題前要做答案驗證與人工可審核流程。
8. 考前儀表板：弱點分布、單元完成率、最近練習與考試倒數。桌面版的「目前弱點」與「最近練習」固定歸入右側摘要欄；手機版保留在可展開的「練習摘要」面板，不占用主要進度與紀錄內容流。

## 介面與操作原則

- 正式介面不得顯示「開發中」、「準備中」、「尚未開放」、「尚未串接」或同類開發進度文字。尚未完成的功能應隱藏入口；服務暫時不可用時，只顯示使用者可理解且可採取行動的狀態，不暴露內部設定或技術架構。

- 操作動線必須簡單，完成主要任務時只要求必要步驟，不讓使用者在多個頁面之間反覆切換。
- 每個畫面只呈現當下任務需要的內容與主要操作，避免同時放入過多功能入口。
- 相關資訊與設定應合併在同一區塊，不使用大量卡片、面板或重複標題切碎內容。
- 進階設定與低頻功能預設收合，需要時再展開。
- 「系統設定」固定使用 `/system-settings`，處理登入帳號身分、一般角色與學習者關係；「學習者設定」固定使用 `/settings`，處理目前學習者的個人資料與學習設定。兩者不得互相取代。
- 在學學習者的系統預設科目依目前年級設定；不在學學習者不套用年級預設。所有學習者都可加入目前適用的有效系統科目，或建立帳號自有科目；一般題目與練習入口只顯示已啟用科目。
- 書籍版本依科目分開設定，科目選項只顯示科目名稱。「全部科目」在選項中縮寫為「全部」。題目總覽與練習在切換學習者後，必須從新學習者的學期與各科書籍版本建立基準篩選條件。選擇單一科目後，可暫時切換版本，且不修改學習者設定。選擇全部時，各科分別沿用自己的學習者版本。
- 只有學習者明確保存、且目前題庫可用的科目版本才能自動帶入。版本未設定或不可用時，介面要清楚顯示未限定或未設定，不得因為當下只有一個選項就猜測成學習者版本。同一學習者的帳號資料在背景重新載入時，不得覆寫使用者當下手動選擇的篩選條件；切換學習者時則必須重建基準，不得沿用上一位學習者的學期、版本或其他篩選選擇。
- 每位學習者可用逗號設定最多 20 個常用題數，數值須為 1 至 500 的正整數，並從清單中選擇一個預設題數。練習頁的題數下拉選單使用這份清單，也可臨時輸入其他正整數，且不覆寫學習者預設值；若目前範圍題目不足，實際練習使用全部可用題目並明確提示數量。
- 總覽、練習設定、題目總覽、錯題、學習者設定與系統設定各自使用固定網址；題目總覽使用 `/questions`，舊 mock 匯入頁 `/bank` 轉址到此頁。正式 PostgreSQL 匯入 API／介面另行交付前不得顯示成可操作功能。成果統計併入總覽，不保留獨立成果導覽；舊 `/results` 必須轉址到總覽。重新整理、上一頁與下一頁後仍需回到網址對應的頁面。
- 總覽的「題庫作答進度」上方使用共用頁籤元件切換科目，選定科目後在下方分列該科各單元進度，不提供其他篩選。各單元總題數以目前學習者可用題庫為準；已作答與答對題數只採用該學習者每題最新一次作答，待人工檢視算已作答但不算答對。沒有可用題目時顯示空白狀態。
- 登入工作區時只載入帳號、目前學習者與可用題庫，不得等待完整作答紀錄、練習場次或錯題佇列。工作區顯示後，只有總覽與錯題排行榜可按需讀取練習歷史；讀取完成前必須顯示載入狀態，不得把尚未讀取誤顯示為沒有紀錄。
- 進行中的專注練習使用獨立網址。重新整理時以瀏覽器保存的伺服器 session UUID 讀回資料庫中已送出的進度，並先顯示為暫停狀態；尚未送出的文字答案與手寫內容不保存。
- 畫面需有明確的主要按鈕；次要操作不得與主要操作使用相同的視覺層級。
- 新增功能時應優先整合進既有流程。若需要增加新的頁面或區塊，必須說明現有畫面為何無法容納。

## 帳號與登入

- 系統必須提供帳號登入；同一帳號可建立及管理多位學習者。
- 每位學習者的題目、練習計畫、作答紀錄、錯題與學習成果必須分開保存。切換學習者時，不得混入其他學習者的資料。
- 主導覽的「系統設定」必須直接從 PostgreSQL 管理帳號身分、有效一般角色與可存取的學習者。`accountRole` 表示主要身分，`activeRole` 表示目前能力；只要仍有有效的 parent 或 tutor 授權，即使 `accountRole=learner`，切到相應 `activeRole` 後也可建立、選取與管理學習者。建立時在同一交易給目前帳號可管理的 `learner_access`。切入受管學習者的 learner 模式後，前端隱藏系統設定，帳號身分、建立、帳號層更新與選取 API 回傳 `403`。只有 self learner 能力的帳號仍可查看自己的系統設定，但不能建立受管學習者。
- 「學習者設定」只處理 session 目前選取的學習者。成人切入受管學習者的 learner 模式後仍可進入此頁；寫入前必須確認有效、已接受、未撤銷的 `learner_access`，且 `can_manage_settings=true`，否則只能查看。
- 帳號可使用電子郵件與密碼註冊及登入。電子郵件註冊頁只收電子郵件與密碼，通過驗證後建立十分鐘有效的 HttpOnly 引導狀態；使用者到 `/quick-register` 選擇帳號身分並建立第一位學習者後，系統才在同一交易建立正式帳號、角色、學習者關係與登入工作階段。未完成引導的狀態不能使用練習或帳號功能。`/account` 的 Google、LINE 與 Facebook 按鈕直接啟動供應商授權，不先開啟平台選擇頁；供應商身份已註冊時直接登入。新使用者完成供應商授權後，也到 `/quick-register` 補充角色與學習者資料。電子郵件已屬於其他身份時停止，不自動合併。帳號綁定仍未交付。
- Google 只要求 `openid`、`email` 與 `profile`；LINE 只要求 `openid`、`profile` 與 `email`；Facebook 只要求 `public_profile` 與 `email`。服務不保存 access token、refresh token 或 ID token。後端驗證供應商不可變身份及電子郵件後，把短效註冊狀態保存在 PostgreSQL；瀏覽器只持有 HttpOnly 不透明 token。使用者補完帳號角色與學習者資料後，服務才在同一交易建立帳號、登入身份、角色、學習者關係與 session。
- 登入、註冊、登出確認、忘記密碼、快速註冊與帳號綁定使用獨立網址，重新整理後仍維持目前流程。本機 PostgreSQL 整合以 `/account` 實際處理電子郵件密碼註冊、登入、登出與驗證信寄送，`/account/verify-email` 完成一次性信箱確認，`/account/forgot-password` 與 `/account/reset-password` 完成本機忘記密碼流程；只有 SMTP 設定完成的環境才會真正寄信。三種社群快速註冊的程式與隔離測試已完成，仍須設定各供應商 App 並完成真實帳號往返驗收；`/account-link` 不得用快速註冊冒充帳號綁定。

一般帳號本身的 `accountRole` 只能是 `parent`、`tutor` 或 `learner`；它表示主要身分，不會覆蓋帳號另外持有的有效一般角色。`system_admin` 是另一條管理授權，不混入一般帳號身分。登入 session 的 `activeRole` 與 `activeLearner` 分開保存，`activeRole` 必須對應有效 `user_roles` 授權，並決定目前可用能力。切換目前操作情境不得改變 `accountRole`，也不得產生新角色或新存取權。

每個一般帳號只能有一位 self learner，且該學習者名稱必須與帳號顯示名稱同步。這項限制不取代 `learner_access` 原有的關係唯一性：同一 `(learner_id, user_id, access_role)` 只能有一筆未撤銷關係，另以每帳號唯一的未撤銷 learner 關係識別 self learner。學習者設定寫入仍須通過有效 `learner_access` 與 `can_manage_settings`。

`learner_access` 是帳號與學習者關係的唯一正式資料表名稱。後續 migration、API 與文件不得另建 `user_learner_access` 或其他平行表名。

## 系統管理員

- 系統提供一個不寫入應用程式資料庫的預設系統管理員。其身分與驗證資料保存在後端部署環境的 Secret Manager（密鑰管理服務），不得放入 Vercel 前端、原始碼、fixture 或可由瀏覽器讀取的環境變數。
- 只有系統管理員可以授予或移除其他資料庫帳號的系統管理員權限。預設系統管理員不出現在一般帳號清單，也不能由管理介面修改或刪除。
- 一般帳號可以修改自己建立或匯入的題目與答案，不得修改其他帳號或系統提供的題目。系統題目只有系統管理員可以修改。
- 每一次管理員權限異動與系統題目修改都要由後端重新檢查登入身分及權限，並留下不可由一般管理介面修改的稽核紀錄。
- 完整資料契約、安全邊界與施工順序定義於[系統管理員與題目異動規劃](system-admin-plan.md)。

## 學習者共享與權限

- 學習者可分享給其他帳號，例如另一位家長或家教，不需複製學習者檔案。
- 所有取得分享權限的帳號，都能查看該學習者的練習計畫與學習成果。
- 學習者資料仍維持單一紀錄來源；不同帳號查看的是同一份資料，不得各自產生互不一致的副本。
- 學習者未分享給某個帳號時，該帳號不得查看其個人資料、計畫、作答紀錄或學習成果。
- 帳號可在已授權的家長、學習者與家教角色間切換。六位數角色 PIN 的設定／重設 challenge、API 與介面已完成，但現行成人角色切換仍以帳號密碼重新確認；角色 PIN 尚不參與角色切換，不得寫成現行切換憑證。
- 切換角色時保留目前選取的學習者，不因角色改變而自動切換學習者。帳號設定需列出每個角色可以管理的學習者；角色未取得目前學習者的權限時，不得切換後存取其資料。
- 角色 PIN 只能透過帳號單一有效且已驗證的電子郵件提出設定／重設，並且目標 parent／tutor 角色在確認時仍須有效。成功後只撤銷該目標角色的 session，不影響同帳號其他角色的 session；SMTP 真實寄送尚未完成。
- 學習者可執行家長或家教建立的練習計畫，但不得修改其科目、範圍、作答方式、題數或進階篩選條件。

目前已串接 `accountRole`、self learner、既有有效角色的 session 切換，以及角色 PIN 的設定／重設：切換目標角色必須已存在於帳號的有效 `user_roles`，切換不得新增角色或改寫 `learner_access`。角色授予／撤銷、角色 PIN 作為切換憑證及 `system_admin` 管理仍未完成；追蹤識別碼記錄在資料庫完成對照。

## 題庫與練習計畫

- 家教可在自己的帳號下建立與管理題庫。
- 左側導覽提供獨立的「題目總覽」。總覽可依關鍵字、科目、學期、版本、來源、單元、主題、知識點、難易度、題型、建立者、來源專屬欄位及收藏清單篩選，並以分頁清單顯示結果；點選題目後，右側顯示完整題目、選項、答案、解析、分類與來源。
- 作答狀態至少包含全部、未做過、做過及最近一次答錯。同一題有多次作答時，以目前學習者最新一筆作答判定；待人工檢視仍屬於做過，但不算答對或答錯。
- 題目總覽、錯題排行榜與開始練習使用同一個可展開的篩選元件及相同的題目查詢規則，避免三個入口對同一批題目產生不同結果。共用元件中的單元、來源、題型與難易度都可複選；同一欄位的多個值以 OR 合併，不同欄位之間以 AND 組合，空陣列表示該欄位不限定。只有開始練習可額外設定本輪題數及難易度比例。
- 收藏清單依學習者分開保存，且可建立多份。題目可同時加入多份收藏；「移動收藏」會先從其他收藏清單移除，再加入目標清單。
- 題目總覽的批次範圍可選「已勾選」或「全部篩選結果」。批次動作支援加入收藏、移動收藏與建立練習計畫；建立計畫時需固定當下題目清單，避免後續變更篩選條件影響已建立的內容。
- 家長、學習者與家教都可建立自己的匯入本。匯入本記錄建立角色及適用學習者；沒有選擇匯入本的題目歸入「系統預設」。匯入紀錄需顯示當次寫入的題本名稱。
- 家教可使用自己的題庫，為已分享給自己的學習者建立練習計畫。
- 學習者可建立自己的練習計畫。
- 每份練習計畫必須記錄建立者與適用的學習者，並與該學習者的作答紀錄及成果連結。
- 取得該學習者分享權限的帳號，都能查看其練習計畫與執行成果，不論計畫由家長、家教或學習者建立。
- 練習入口需在標題右側顯示目前學習者的連續練習天數；天數依臺北日期從作答紀錄計算，同一天多次作答只計一天，今天尚未作答但昨天有紀錄時保留既有連續天數。
- 建立練習企劃時，題目條件預設收合，直接使用與題目總覽相同的篩選元件，不另設「篩選方式」選擇器。答案檢核方式另列為「練習方式」。學校等學習者基本資料只在學習者設定維護，不在單次練習重複輸入。
- 練習篩選使用共用的科目、學期、版本與題目條件，只額外提供難易度比例與本輪題數。未指定的複選欄位以空陣列保存，表示該欄位不限定。
- 練習設定需依目前選取的科目、章節或考試範圍及進階篩選條件，顯示總題數、已練習題數、完成百分比與已檢核正確率。同一題作答多次時只採用最新一次紀錄；待人工檢視的作答不計入正確率。
- 難易度分為基礎、中等、進階。一般難易度篩選可複選，選中任一值就符合該欄位。開始練習另可啟用比例模式；啟用後，一般難易度條件停用且不參與選題。三者占比合計必須為 100%，系統會依比例選題；個別難度題目不足時，再由其他符合條件的題目補足本輪題數。

## 題目匯入與年級

- 「新增題目」先建立登入帳號專屬草稿。學生、家長、家教與不在學的社會人士都可使用；建立草稿時不要求先選題庫、科目、年級、學期或其他分類。
- 手動新增題目必須先選擇範本。首版提供單選題、圖片選擇題、複選題、是非題、填空題、多格填答題、簡答題，以及題組與子題。選取範本時使用正式練習元件展示題目、作答區、參考答案與解析；套用後建立完整可編輯草稿。範本只協助建立既有題目結構，不新增另一套正式題型資料。
- 範本預覽使用團隊自行編寫、可直接作答的原創題目，不複製正式題庫或教材內容。只有題組與子題範本保留結構化表格，其他範本以一般文字題呈現，避免讓使用者誤以為每題都需要表格。圖片選擇題在選擇範本時顯示四張可辨識的示例圖，套用後仍只建立圖片位置，由使用者上傳自己的圖片。
- 一般使用者常見的語文練習必須直接出現在範本示例中。填空題示範看注音寫國字，多格填答題示範依中文意思填寫多個英文單字；使用者套用後可直接替換題幹與答案，不需要先理解內部題目結構。
- 共用題目文字元件需保留單一注音音節的既有直式呈現。兩個以上以空白相鄰的注音音節須使用題幹原字級橫排，整組不換行，不能再拆成高度隨字元數改變的直欄；題幹不得在注音旁補出對應國字，以免洩漏填空題答案。
- 手動新增與格式匯入共用同一份範本清單及選擇元件。格式匯入可選擇一種、多種或全部題型，並依選取結果產生可複製的 AI 指令、多題 JSON 範例與下載檔。每題保存自己的 `templateId`，因此同一份檔案可包含不同題型。載入時必須檢查 `templateId` 與小題、作答方式及選項結構一致。
- 格式匯入的 AI 指令必須要求模型依作答結構選擇允許的 `templateId`，不得把題號、章節序號、題型名稱或配分文字寫入題幹。原稿題號及頁碼只保存於來源欄位；無法確認的內容不得猜測。來源沒有答案或解析時使用空陣列與人工檢視，不得抄用範例內容。每個圖片或頁面裁切參照在整份 JSON 中必須唯一。
- 更換範本時保留題目內容、分類與匯入追溯資料，重建作答設定、選項、答案、提示與解析。拍照、PDF 與格式匯入依既有小題結構顯示最接近的範本，使用者可在校對時更換。
- 來源題號與來源頁碼不顯示於手動新增介面。拍照與 PDF 的頁碼由系統保存；格式匯入可提供選填的來源題號與頁碼，供版本追溯與稽核使用。
- 草稿只保存在 `import_batches` 與待確認的 `import_items.draft_payload`，不建立 `questions` 或 `question_revisions`，不出現在正式題庫、練習、額度統計或學習成果。
- 草稿可反覆編輯並以正式練習元件預覽；預覽輸入不建立 session、作答或判分紀錄。
- 題目編輯區沿用正式練習的單題流程，一次只顯示一題，並提供題號進度、上一題、下一題與新增下一題。編輯內容依大題說明、小題內容、作答方式、答案、解答與解析、作答前提示的順序排列。掃描後的桌面介面並列原稿與目前題目，窄螢幕改為上下排列；「新增小題」位於目前題組底部，批改方式與父子題關係收在「更多設定」。切換原稿的去手寫、彩色、灰階或黑白版本只改變校對畫面，不得替換題目內已建立的裁切圖片。
- 圖片草稿須保留從原始檔重新分析的入口。重新分析成功時，以同一交易替換尚未發布的題目候選；分析失敗時保留原草稿，不得留下只更新一部分的結果。
- 圖片或 PDF 草稿進入編輯畫面後，必須顯示可辨識的原始檔入口。圖片以可點擊縮圖開啟完整預覽；PDF 可在預覽視窗閱讀並另開原檔。原始檔仍經登入帳號與資產擁有權檢查，不得把儲存路徑或公開網址放入草稿內容。
- 同一份草稿可一次上傳最多 20 份圖片或 PDF，並保留使用者選取的檔案順序。每份原始檔可標示為題目、答案、解析或補充圖片，也可交由固定本機模型判斷。模型判斷必須保存用途、信心值與理由；使用者可在草稿中改正用途並重新分析。只有題目來源可建立題目，其他來源只作為答案、解析或補充證據。
- 來源沒有已印出的答案時，本機模型可以依題目內容提出答案建議；有答案頁或解析頁時，應優先使用該來源並保存來源文件與頁碼。答案建議只保存在背景工作的完成結果，不直接改寫草稿。使用者按下「套用答案」後，答案與解析才進入可編輯草稿，且仍須在加入題庫前校對。
- 手動編輯、格式匯入與掃描校正共用同一套有序內容區塊。題目內容、小題內容、每個選項、作答前提示及解答與解析都可包含文字、圖片、公式與表格，重新開啟草稿或發布後不得遺失非文字內容。
- 給外部 AI 使用的交換格式不得包含內部 `assetId`、Base64 圖片或遠端圖片網址。一般圖片使用 `image_ref`；原始照片或 PDF 中的區域使用 `crop_ref`、頁碼與 0 至 1 的比例座標。使用者補上檔案後，系統才把參照轉成登入帳號持有的私人資產。未補齊的格式不能建立草稿或發布。
- 新增題目的拍照、掃描原稿、格式檔與內容圖片必須共用同一套檔案來源元件。主要入口使用作業系統檔案選擇器，不附加相機限制；平板或手機已安裝並啟用的 Google Drive、iCloud Drive 等文件提供者由作業系統列出。拍照使用獨立入口並優先開啟後鏡頭，避免裝置檔案與雲端來源被相機模式取代。
- Google Picker 是選配的網頁 Google Drive 入口。只有環境已完整設定 OAuth client ID、Picker API key 與 Cloud project number 時才顯示；未設定或設定查詢失敗時隱藏，不讓使用者進入必然失敗的流程。授權只在使用者選擇檔案時提出，使用 `drive.file` 存取使用者明確選取的檔案。Lerniqa 下載檔案後重新驗證內容、大小與 MIME type，並保存到自己的私人資產；題目不得依賴 Google Drive 網址或長期保存 Google access token。
- 圖片目前正式接受 JPG、PNG 與 WebP；掃描原稿另接受 PDF，格式檔接受 JSON。HEIC／HEIF 尚未提供可靠的伺服器解碼時必須明確拒絕並提示先轉成 JPG，不得將副檔名改名或用未驗證結果冒充轉檔成功。
- 每個可作答小題可有零至十組作答前提示。題目範本不得預先建立示範提示；只有使用者主動新增，或來源明確提供提示時才建立。編輯器沒有提示時只顯示小型「新增提示」按鈕，有提示時才顯示區段標題與提示內容。正式練習預設收合，學習者每次只展開下一組；提示不參與判分，也不取代作答方式自動產生的格式說明。解答與解析仍依練習的答案揭露規則於作答後顯示，作答前不得取得解析圖片。
- 圖片選項的正確答案仍保存為同一小題的選項鍵值，沿用自動判分。圖形解答或答案示意圖放在「解答與解析」。學習者上傳圖片作為答案需要獨立的附件批改規格，不屬於本輪新增題目能力。
- 「加入題庫」與「儲存草稿」是分開的動作。加入題庫只要求科目；年級、學期、版本、難易度、來源與帳號自訂分類均可留空。系統依題目的作答方式選擇內部標準題型；編題範本不會成為另一個必填分類。
- 每個帳號可建立自己的科目，以及只適用於該科目的單選或複選分類欄位與選項。設定由同帳號的學習者共用，其他帳號不可讀取或引用。
- 每題可分別套用自訂分類。AI 只能從目前科目既有的有效選項提出含信心值與理由的候選；候選須經使用者逐筆或整批確認後才寫入草稿，不能自行建立選項或直接發布。
- 圖片或文件文字若能完整對上既有單元名稱，系統可預填該單元所屬的科目、年級、學期與版本。名稱重複時，必須再以來源文字中的科目、年級、學期或版本判斷；仍有多個候選就維持未設定。預填結果只出現在「加入題庫」確認畫面，不能直接發布。
- 使用者切換至在學學習者後，拍照或上傳的教材題應自動帶入該學習者目前設定的年級，不必再次選擇。
- 自動帶入的年級必須寫入題目資料，作為後續分類、出題與搜尋相近題目的依據；來源規則標示年級不適用時不得寫入年級。
- 使用者可在題目校正時修改自動帶入的年級，或依來源規則改為不適用。
- 在學學習者尚未設定年級時，匯入教材題的流程需改由使用者手動選擇年級後才能繼續；來源明確標示年級不適用時不套用此限制。
- 題庫可收錄不綁年級的語言檢定與國家考試題目。這類來源將年級標記為不適用，改以正式考試體系及級別分類；匯入時不得要求建立虛構年級。
- 學習者可設定為在學或不在學。在學者必須選擇目前年級；不在學者不保存年級、學期或學校，科目由其科目設定決定。
- 學習者可為考試科目設定目標級別。首版練習只選相同級別題目；是否同時納入較低級別，需另行確認產品規則。
- AI 拆分完成後必須依原始順序列出所有題目與參考答案，不得只顯示第一題或抽樣結果；使用者確認全部題目後才能寫入題庫。
- 題目工作台左側只提供「建立題目」與「我的草稿」兩個主要入口。「建立題目」右側以「檔案上傳」、「格式匯入」與「手動編輯」分頁切換，預設開啟「檔案上傳」。檔案上傳、格式匯入、手動編輯、草稿清單與單一草稿分別使用 `/questions/new/upload`、`/questions/new/import`、`/questions/new/edit`、`/questions/drafts` 與 `/questions/drafts/[batchId]`；舊 `/questions/new` 導向檔案上傳。切換建立方式不得清除尚未送出的檔案或編輯內容，重新整理、瀏覽器上一頁與直接開啟網址必須恢復該網址對應的畫面。
- 拍照、圖片或 PDF 上傳成功後，工作台立即開啟該來源的草稿編輯畫面，不等待 OCR 與本機模型分析完成。分析期間顯示處理狀態；通過題目契約的結果才寫入草稿清單，分析失敗時保留原始檔與錯誤訊息，不建立假的空題目。
- 圖片與 PDF 分析必須由持久背景工作執行。使用者離開或重新整理頁面不得取消工作；「我的草稿」顯示等待分析、背景分析中、可編輯或分析失敗。worker 中斷後由租約逾時重試，且同一草稿同時只能有一個有效工作。背景分析期間不得編輯舊候選，避免完成結果覆寫使用者剛修改的內容。
- OCR 出現「一、國字注音：每字1分，共10分」等章節標題時，章節序號、題型名稱與計分說明只用來判斷題型及作答方式，不寫入題幹。標題下直接排列的阿拉伯數字題號各自建立為獨立題目，並以「章節序號-題號」保存來源題號及檢查漏題。只有共用文章、圖片或表格本身是後續多個問題不可缺少的作答內容時，才建立題組與小題。
- 圖片解析每次都把校正頁面、OCR 全文、各 OCR 行的比例座標與信心值交給固定本機 vision model。圖片是抄錄依據，OCR 只供定位；不得因 OCR 字數足夠就省略圖片。低解析度頁面只在送入模型的副本上以 Lanczos 放大並銳化，不能把放大後像素當成原稿新增的細節。
- 模型結果通過 JSON 格式仍不代表內容可靠。國字注音題必須保留原稿的作答位置，不得補成完整詞語、答案或整詞讀音。模型輸出的注音必須在 OCR 候選中找到完全相同的字串；缺少相同候選時，即使每個字元都是合法注音，也必須改用緊密原圖裁切交由使用者確認。草稿編輯器須讓使用者放大裁切圖，並在原位置輸入注音；輸入只接受注音符號、聲調、空格及成對的原稿引號或括號。確認前不得移除裁切圖，確認後只替換該內容區塊。若模型輸出含替代字元、把章節分類寫入題幹、把注音移到作答位置外、含空白括號、拉丁字母、日文假名，或在同一括號混入國字與注音，系統須要求模型重新對照原圖一次。第二次仍不可靠時拒絕建立新題目並保留既有草稿。
- 每一題可分別設定科目、書籍版本、單元、主題、難易度與來源。單元記錄題目在教材中的位置，例如第幾章、第幾課或 Unit；主題記錄跨書籍版本共用的學習內容，例如分數加法或近義詞。同一個主題可出現在不同版本及不同單元。
- 一題可歸入多個教材單元。題目原本不屬於特定出版社版本時，例如會考、基測或校內卷，仍可依教學需要對照到不同版本的章節，但不得因此把題目的原始版本改成該出版社版本。
- 使用者在「加入題庫」確認單元後，系統必須把單元關聯寫入正式題目版本；只顯示於表單但未保存的單元不算完成分類。
- 官方課綱代碼與平台知識點分開管理。`N-7-5`、`Da-IV-1` 等代碼需保存課綱版本及正式代碼；知識點則用於平台內的教學、複習與相近題關聯，兩者不能混成同一清單。
- 題目內容支援文字、圖片、公式、表格、原頁裁切圖及音訊。表格內容在題目總覽與正式練習都必須依來源列、欄顯示為有格線的語意表格，不得退化成以空白對齊的純文字；窄螢幕由表格容器提供橫向捲動，不得撐寬整頁。英聽音訊需連結對應錄音稿，讓匯入、預覽、練習與無障礙呈現使用同一份內容資料。
- 版本、單元、主題與來源均可選擇既有項目。每個選單的最後一項提供新增入口，選取後可直接輸入新項目。
- 科目、版本、單元、主題、難易度與來源均為選填；留白時由 AI 依題目與檔案內容提出建議，使用者確認前不得直接寫入。
- 匯入來源支援圖片、PDF、文件與直接貼上文字。來源中包含多題時，必須列出全部題目，不得只顯示第一頁或第一題。舊版 Word 檔必須先隔離原檔並停用巨集；只有經轉換且確認不含 VBA、Macro 或 ActiveX 的 DOCX 衍生檔，才能作為 `clean` 來源。
- 上傳檔案與貼上文字使用同一個匯入區塊的分頁切換。檔案頁需支援拖放與點選檔案，並在寫入前顯示目前選擇的檔案。
- 題目中的圖片、數學圖形與題幹需保持關聯並依原始順序編排；校正時可替換、移除或重新指派附圖，避免 AI 拆題後圖片配對錯誤。
- `crop_ref` 只允許引用同一份原始照片或 PDF。系統先完成透視校正、影像模式與手寫處理，再依比例座標裁切。本地模型的裁切參照名稱不得作為可信任識別；系統須依題目與內容位置建立整份分析結果內唯一的參照，再執行題目契約驗證。介面顯示原頁、裁切框與結果，並允許使用者修改左側、上方、寬度與高度後重新裁切。
- 來源文件中每題附帶的欄位都必須保存，例如題目編號、難易度、出處、認知向度、知識向度與課名。系統不得只取目前畫面用到的欄位後捨棄其他內容。
- 文件欄位需同時保存原始標籤、原始值、標準鍵值、可篩選值、判定來源與信心值。新增欄位後，題庫查詢與練習進階設定應能依資料自動產生篩選選項，不需新增固定程式分支。
- 來源類型需支援舊綱題、會考、同步練習卷、基測、素養題、一般試題及後續新增類型。若文件提供年份、學年度或梯次，需分欄保存並可複選篩選。

目前的題庫補全程式只處理已發布的系統題目，對細題型、主要知識點與解題方法提出結構化建議。命令預設為 dry-run，目前 279 題沒有套用補全結果；`0012` 已提供資料表，但允許寫入時仍只能建立 `pending` suggestion。建議必須先通過品質抽檢與人工核准，再由另一個受權 apply 流程修改新的題目版本，不得直接改寫現有已發布 revision。

## 題目與手寫作答

- 選擇題與是非題可使用既有的選項式作答介面。
- 題目必須保留來源文件的原始題幹、選項、答案、解析、題型名稱與順序，不可為了配合介面改寫成另一道示範題。
- 寫出國字與注音、注釋、改錯及填充等書寫題不得建立選項。配合題、選詞測驗與題組需保存每一個小題及其選項，作答時逐小題收集答案。
- 每一題都必須在題目旁提供大型手寫板，讓學習者保留計算過程或直接寫下答案。
- 練習時使用專注版面，不顯示工作區側欄、摘要或其他功能區塊；桌面版為左側題目、右側手寫板，窄螢幕改為上下排列。
- 練習右上角提供關閉入口，學習者可暫時關閉並保留已送出的進度，或結束練習並捨棄尚未送出的本題內容。
- 學習者從題目總覽的單題詳情開始練習時，練習 session 必須保存該題的返回目標。暫時關閉練習、尚未作答即結束練習，或從練習結果離開時，系統必須返回原本的 `/questions/{questionId}`。從練習設定或錯題入口開始的 session，仍返回各自原本的清單頁。
- 練習畫面不提供鍵盤計算筆記；書寫題可保留文字答案欄位。以手寫補足文字答案時，送出後建立本地 AI 分析工作；使用文字欄位時仍依題目判分政策處理。
- 同一題包含多個可獨立作答的小題時，作答區一次只顯示一個小題，並提供上一小題與下一小題切換。切換小題不得清除已輸入答案，也不得自動送出或自動前進。共用題幹與圖片在切換時保持可見。題幹多空格題與多欄文字小題依下一條規則同頁顯示，不套用逐小題切換。
- 題幹本身已有足量空格且每個文字小題各對應一個空格時，輸入欄位保持同行顯示，不使用逐小題切換。多欄文字小題也必須在同一頁顯示全部小題列，每列輸入欄位前顯示與題幹一致的可見小題編號，例如 `(1)`、`(2)`。這條規則同時適用於每個小題只有一個欄位，以及同一小題有多個欄位的資料。編號不得只存在於無障礙文字，桌面與手機的實際顯示字級都不得小於 `1.125rem`。輸入列不重複顯示題幹、公式、「文字答案」或人工批改提示。
- 多小題的參考答案必須依小題順序顯示 `(1)`、`(2)` 等可見編號；答案資料只保存可接受值，不把編號混入可判分文字。單一小題不增加額外編號，來源答案尾端已有分號時不得產生重複分號。
- 結構化數學公式使用隨 KaTeX 套件提供的數學字型與 display style；共用公式容器在題幹、作答與解答中的實際字級不得低於 `1.5rem`，避免分數的分子與分母再次縮小。含結構化公式的多行題幹使用專用列高，相鄰兩列公式盒子之間必須保留可見間距；一般文字題幹維持原本列高。純文字解析中的 `\\frac{分子}{分母}` 使用共同行內分數元件，字級不得小於相鄰解析文字，分數線須和同列等號維持同一視覺中心。`\\phantom` 表示來源題目刻意保留的作答空格，不得當成破圖或自動補數字。驗收必須在 Chrome 實際量測公式、公式列距、解析基線與輸入列編號，不能只確認公式 DOM 已產生。
- 題幹、選項、解答與解析的純文字在學習者畫面中把 `∵` 顯示為「因為」，把 `∴` 顯示為「所以」。這項規則只改變前端顯示，不改寫來源內容、資料庫欄位或搜尋文字；管理與來源審核畫面仍保留原始字元。
- 可編輯的文字答案欄位使用與選項卡一致的邊框、圓角、背景與焦點提示。唯讀的手寫辨識結果不套用可編輯狀態樣式。
- `instant` 與 `complete` 的手寫內容必須跟隨該題答案保存，並可在答案審核與歷史作答中重現。`score` 不保存逐題答案或附件。
- 手寫板提供畫筆、橡皮擦與清除功能；說明文字與工具列集中在標題區，避免壓縮可書寫空間。
- 練習結果有手寫內容時，桌面版在題目右側顯示原始手寫；沒有手寫時，題目內容使用完整寬度。
- 題庫細題型決定手寫辨識方式。「寫出國字、注音」使用單一字元辨識；「注釋」使用保留字距與順序的單行多字辨識。兩者都把辨識結果填入唯讀的文字答案欄位，只接收手寫圖片，不接收題幹、參考答案、解析或評分規則，也不解題或判斷正誤。辨識結果不可覆蓋原始手寫內容。

目前實作只在 `instant`／`complete` 作答提交時儲存通過驗證的 private PNG，並由作答與學習者權限鏈取回。文字小題沒有其他答案時，手寫只能保持 `pending`／`manual`；同題已有完整文字或選項答案時，手寫圖只作為第一個小題的計算過程附件，不參與判分。`score` 在任何逐題檔案寫入前拒絕手寫提交。上述程式已通過針對性測試，但尚未在整合 `0012` 後完成資料庫 E2E。

手寫 AI 使用 `0012` 的 job／run sidecar、受控 worker 與本機 Ollama。worker 固定核對模型 digest、vision capability 與原始 PNG checksum，並依題庫細題型套用單一字元或單行多字模式；只把手寫圖片及固定辨識指令送給模型，保存辨識文字、可讀性、信心值與不確定原因。sidecar 的相容欄位固定保持 `pending`，不得產生 `correct` 或 `wrong` 建議，也不得改寫 `answer_part_results.current_result`、錯題佇列或統計。只作為計算過程的手寫附件不進入 AI 佇列。合成品質樣本、四張單字真實筆跡及一張單行雙字真實筆跡已通過；人工檢視介面仍待驗收。

## 作答與檢核模式

開始練習前可選擇下列模式：

- 全部作答後檢核（`complete`）：學習者完成整份練習前，不回傳逐題判定、參考答案或解析；完成後才提供逐題明細。
- 逐題檢核（`instant`）：每完成一題就提供該題判定，適合由家教或家長陪同練習。
- 只顯示成績（`score`）：完成整份練習後保存並只顯示總題數、答對、答錯、待檢視與正確率，重新整理或重新開啟後仍可讀回這份 session aggregate。每個已送出項目只留下不含答案與判定的冪等收據；不保存逐題答案、判定、附件、審核、錯題／相近題佇列、來源追溯或統計 outbox，也不顯示參考答案或解析。

逐題檢核時，系統應在檢核完成後顯示下一題。`instant` 與已完成的 `complete` 可從錯題建立「相關題目練習」；`score` 不保存逐題來源，不得提供這個動作。歷程與錯題佇列必須遵守相同的揭露時機：`complete` 未完成前不得藉由其他端點看出結果，`score` 在任何狀態都不得以明細或錯題新增情況洩漏逐題結果。

歷程必須使用建立練習時固定的題目 revision。舊 revision 沒有可安全顯示的快照時，只顯示當時結果、時間與題目內容無法安全顯示的提示，不得拿目前版本冒充。恢復進行中的 session 時若固定 revision 與可用題目內容不一致，應把舊 session 標記為 `abandoned`，保留可保留的歷史狀態，並要求學習者建立新練習。

每個小題需設定判分政策：系統自動判分、人工檢視或 AI 輔助後人工確認。已發布或已取代版本中的自動判分選擇題、複選題及是非題至少要有一個屬於同一小題有效選項的答案鍵；自動判分文字題至少要有一個非空白可接受答案。人工檢視與 AI 輔助後人工確認的小題可以沒有參考答案。系統不得為了通過發布或升級而猜測、補造答案；資料不完整時必須停止。書寫題及 AI 手寫辨識結果在未確認前保持待檢視。`instant` 與 `complete` 的作答紀錄需保留原始答案、當時題目版本與原始判定；若需修正結果，必須新增人工審核紀錄，不得覆寫原始作答。`score` 只保留 session aggregate 與不含答案／判定的冪等收據，不建立可供檢視的逐題內容。

## 答案審核

- 檢視答案時，可切換至審核者身份。審核者身份需可定義，首批支援家長與家教。
- 審核畫面可設定是否同時顯示參考答案與學習者手寫內容，預設為顯示，以便直接比對。
- 關閉答案比對時，審核者仍可查看學習者原始作答，但參考答案不應出現在同一畫面。
- AI 手寫辨識結果需與學習者原始手寫內容分開呈現，讓審核者能修正判定。

## 錯題與相近題

- 學習成果中的每次練習明細提供「全部題目」與「錯題」分頁，預設顯示錯題；全部題目需保留每題原始題號及作答結果。
- 每道可揭露的錯題提供「立即測驗」與「相關題目練習」。立即測驗只重做原題，題組中的小題也不得自動擴成整組。相關題目練習先找題幹文字骨架與解題邏輯相同、只替換數字或名稱等可變值的題目；再使用已確認相似群組及正式關鍵字、人物、作品、篇章、主題或知識點的共同數量，依關聯由近到遠遞補。共同關聯越多越優先；同一相近程度內尚未作答者優先，最近已答對者排除，只有較相近層級沒有符合條件的候選時才往較不相關的層級尋找。所有判定依據必須已寫入資料庫或可追溯的版本化來源，不得用同科目、同單元或未核准的即時 AI 猜測直接建立關係。
- 歷史錯題可個別勾選是否產生相近題目，作為再次考核內容。
- 歷史錯題與歷史練習明細不受學習者目前年級、目前啟用科目或目前書籍版本限制。從歷史錯題產生相近題時，以原題的年級與分類為選題依據。
- 每道歷史錯題需顯示其相近題目的累計結果：已完成題數、答對題數與答錯題數。
- 相近題必須能追溯至原始錯題與知識點，避免同一題在不同錯題紀錄中重複計算。
- 產生相近題目後，學習者可選擇立即練習或加入後續練習。
- 題目總覽與練習篩選需提供「錯題與相近題」範圍。選取後列出目前學習者最近一次仍答錯的題目，以及與這些錯題已有明確關聯的相近題。沒有相近關聯的錯題仍需保留在結果中。
- 相近題不能只因科目、單元、知識點或題型相同就視為同一類。只有資料庫中已建立並確認的相近關聯，才可用於篩選與排除；關聯判定方法與審核規則另行制定。
- 自動分析只能建立附有方法版本、分數與判定依據的相近題候選。候選分數只用於安排人工審核順序；候選經核准並寫入正式相近題群組前，不得影響篩選、排除已掌握題組或練習選題。題目改版後，使用舊版本內容分析的候選需失效並重新評估。
- 相近題篩選需提供「排除已掌握題組」選項。對同一位學習者，同一相近題組中至少有兩個不同題目的最新已檢核作答為答對時，開啟此選項後排除該題組的所有題目。相同題目重複答對只算一題，待人工檢視不列入計算。
- 是否排除只影響當次查詢與出題結果，不得刪除題目、相近關聯或歷史作答。沒有相近關聯、關聯尚未確認，或群組內少於兩個不同題目答對時，不得套用排除規則。

## 作答統計與錯題排行

- `instant` 與 `complete` 每次送出的作答都要新增一筆不可覆寫的紀錄，至少保存學習者、題目、當時題目版本、練習、答案、判定結果、耗時與送出時間。人工改判需另留審核紀錄，不得改寫原始作答。`score` 只保存 session aggregate 與每個已送出 item 的不含答案／判定的冪等收據，不建立作答、小題結果、附件、審核、錯題／相近題佇列、來源追溯或 outbox。
- 每位學習者與每道題目需可查出總作答次數、已檢核次數、答對次數、答錯次數、待檢視次數、第一次作答時間、最近一次作答時間及最近結果。
- 題目統計需能依科目、年級、版本、教材單元、知識點、標準題型、相近題群組與日期區間篩選。相同題型與相近題是不同概念，不能互相取代。
- 錯題排行榜提供個人與社群分頁。個人榜只使用目前學習者的歷史作答；社群榜排行已發布的系統題目，不排行學習者，也不納入帳號自有題目。社群榜只顯示聚合後的總作答次數、答錯次數、不重複作答人數、不重複答錯人數與錯誤率，不得顯示或提供反查個別學習者的資料。
- 社群榜需有已生效的統計隱私政策，且每道題目在查詢期間的不重複學習者數達到政策門檻後才顯示。未達門檻的題目整列省略，不顯示實際樣本數。跨日查詢需對整段期間重新計算不重複學習者，不能直接加總每日人數。
- 原始時間使用含時區時間保存；每日、每週與每月統計以 Asia/Taipei 日期計算，不得依伺服器所在時區分組。
- 明細型統計與排行榜屬於可重建的衍生資料，依 `instant` 與 `complete` 的原始作答紀錄重建；統計更新失敗時不得修改或補造作答明細。`score` 的 session aggregate 是刻意不保留逐題答案內容的結果，不得用目前題目或推測資料補造明細。
- 大量資料下可使用每日彙總與常用期間的實體化檢視加速查詢，但必須保存最後更新時間、可重算範圍及處理進度，讓延遲與漏算可被發現及修復。

## 重要資料模型
正式資料庫的實際資料表、欄位、關聯與限制，以 `database/migrations/0001` 至 `0022` 的原生 SQL schema 為權威；二十二個 migration 合計 124 張業務資料表，隔離資料庫往返驗證已通過。`0020` 至 `0022` 尚未套用持久本機資料庫。[題庫資料庫設計](question-database-design.md)說明完整契約，[正式資料庫完成對照](database-completion-matrix.md)負責對照產品需求與串接狀態。本文件不另維護第二份表名清單。

關聯要求：一個帳號可關聯多位學習者，一位學習者也可授權給多個帳號；登入方式需關聯至同一帳號；題庫與帳號建立的題目需記錄擁有者；系統題目需有明確來源標記；練習計畫需記錄建立者與學習者；題目能追溯原始檔案及頁碼；學習者作答有時間戳並連結當時的題目版本；更正題目、答案或解析不得覆寫歷史作答的判定依據；手寫附件需連結到題目及作答紀錄；相近題需連結到原始錯題；正式目錄種子資料需保存版本、來源、內容雜湊與套用結果；管理員權限異動與系統題目修改需留下稽核紀錄。

`QuestionSimilarityGroup` 代表一組經分析後認定為相近的題目，至少保存群組識別碼、狀態、建立來源、判定方法版本及建立時間。`QuestionSimilarityMembership` 保存題目與群組的多對多關聯，至少包含群組識別碼、題目識別碼、關聯狀態、判定依據、信心值及審核資訊。同一題可依後續規則加入多個群組；查詢時只使用已確認的關聯，關聯異動不得改寫既有作答紀錄。

## 品質／隱私
- 未成年者資料預設不公開；採最少蒐集。
- OCR 與生成結果不可默默當作已驗證正確答案。
- 影像、PDF 與文件上傳需檔案大小、型態、權限驗證及惡意內容掃描。含巨集的原始文件只能隔離與留存證據，不能直接成為題目來源或被下載執行。
- 文件可能涉及教科書著作權：僅允許使用者有權使用的教材，分享功能另設限制。
- 需依臺灣個資法與適用兒少規範設計權限、資料刪除與保存期限。
- 每次讀取或修改學習者資料時，都必須依帳號與學習者的分享關係檢查權限，不可只依前端目前選取的學習者判斷。

## 目前交付範圍

主應用保留多科目導航、學習者、題目篩選、練習、錯題與成果流程。正式匯入的 279 題接入既有 `/practice`，分類為「國語 → 國一 → 翰林版 → 第一冊 → 第四課」。舊 JSON HTTP 契約已封閉；尚未資料庫化的功能必須明確標示為瀏覽器狀態或未完成服務，不得再用 JSON 寫入暫代。

`/account`、`/system-settings`、`/settings` 與練習持久服務使用本機 PostgreSQL；`/local-practice` 只保留內部診斷與相容用途。使用者可用電子郵件與密碼建立 session，再從 `/practice` 依該帳號的學習者權限讀取已發布題目、以三種答案檢核方式建立練習並送出作答。已在同一裝置成功登入的帳號會列入帳號選擇器；選取後由伺服器依可撤銷的裝置憑證簽發新 session，也可登入其他帳號或從該裝置移除快速切換資格。瀏覽器不得保存密碼、帳號 session token 或可識別帳號清單，只保存 HttpOnly 不透明裝置憑證；帳號關聯與撤銷狀態保存在 PostgreSQL。`instant` 與 `complete` 保存需要的作答歷程；`score` 只保存可在重載後讀回的 session aggregate 與不含答案／判定的冪等收據。正式主流程先讀取目前登入狀態，驗證失敗時清除帳號範圍狀態並導回帳號頁，不得改用 fixture 或預設測試身分。登出、session 到期、角色、目前學習者或目前帳號改變時，其他已開分頁會重新驗證 `auth/me`，清除失效的工作區或載入新的操作情境；頁面重新取得焦點與恢復可見時也會重新驗證。瀏覽器只保存非識別性的 UI 設定，以及尚未切換 PostgreSQL 的計畫、排程與收藏。題庫 API 的完整篩選查詢單頁最多回傳 500 題；工作區啟動則只發出一次不帶分類參數的受權限題庫請求，由資料庫依目前學習者可存取的有效題庫、年級、已啟用科目及該科設定的書籍版本決定範圍，不維護前端課次清單。知識點來自 `question_revision_knowledge_points`，不再以題型名稱代替。production 帳號生命週期、學習者剩餘欄位、偏好、考試、計畫／排程／收藏、真實匯入、OCR、AI 出題、真實筆跡品質驗收及 AI 建議人工審核介面仍列入後續階段。

工作區啟動題庫只包含目前發布版本的題幹、小題、選項、顯示 metadata 與知識點，不得包含標準答案或解析。若學習者沒有符合權限與設定的題目，回傳正式空集合，不以內建分類補題。五個分類欄位必須全數提供才是分頁篩選查詢，部分欄位一律拒絕；練習完成後只重新讀取歷程與錯題摘要，不得再次下載完整題庫。既有 session 恢復仍以 session item 固定的 revision 為準，不得用目前發布版本替換。

`0014` 已建立文字模板、可變值、正式關鍵字與題目版本關聯，`0015` 要求 AI／規則產生的關鍵字目錄也先停在 pending。推薦 API 只讀取已確認關聯，依相同模板、已確認相似群組、共同正式關鍵字最多及共同主題最多逐層選題，並保存實際命中證據。來源題型與同單元不再產生新推薦，舊值只供歷史 session 相容。離線分析先產生可查核檔案，另一步只寫 pending；管理員頁面以授權、冪等交易與稽核紀錄執行核准或退回。279 題尚未完成全量分析與人工核准，目前只有一題煙霧測試的待審資料，confirmed 關聯仍為 0，不能宣告已有正式相同／相近題內容。

`0012` 已整合帳號復原 identity binding、同題型歷史來源值域、題庫補全 pending suggestion 與手寫 AI sidecar，且不包含 SMTP outbox。`0013` 以正式目錄資料建立國小、國中、高中共十二個年級與上下學期；`0014` 建立可審核的相同／相近題正式關聯契約；`0015` 補上 AI／規則關鍵字目錄的 pending 與審核證據。

Ollama 服務、固定模型 metadata、digest 與 vision capability 已核實，但這只證明執行環境可辨識模型能力；目前沒有手寫 inference 或品質樣本驗收。AI sidecar 仍是 schema／worker 契約規劃，模型未來也不得直接改寫作答判定、錯題佇列或統計。

## 本機 PostgreSQL 整合契約

- 正式匯入題庫目前包含國語／國一／翰林版／第一冊／第四至第六課。三份核准來源各自綁定正確課次、固定檔名、原檔雜湊與預期題數，並保留文件內來源欄位；共 817 題已持久保存。其餘 12 份文件尚未匯入，需先確認各自的教材分類。
- 題目 API 不得在作答前回傳標準答案或解析。作答必須由伺服器判分；只有判分政策為自動判分且已有完整標準答案的小題可以判為對或錯，其他小題保持待核對。
- `instant` 與 `complete` 的練習、作答、逐小題結果、錯題佇列與 `analytics_outbox` 必須寫入持久 PostgreSQL；`score` 保存 session aggregate 與不含答案／判定的冪等收據，不建立逐題明細、佇列或 outbox。重開 Next.js 或本機 PostgreSQL 後，允許顯示的歷程與 aggregate 仍須可讀取。進行中的 session 可依 UUID 恢復並暫停；若固定 revision 不一致就把舊 session 標記為 `abandoned` 並要求建立新練習。從任意題直接作答時，要繼續尋找尚未送出的題目，只有全部題目都送出後才完成。未送出的文字與手寫內容不在恢復範圍。
- 舊 `score` 逐題資料升級後必須移除；五張可重建統計表只從仍可保留的 `instant` 與已完成 `complete` 明細重建。只由舊 `score` 作答引用的 private 手寫／一般答案附件需解除引用、標記刪除並排入物件清理工作，共用 asset 保留。資料庫清理完成不代表外部物件已刪除；只有 worker 實際確認後才能完成工作並寫入物件刪除時間。
- `/account` 提供電子郵件密碼註冊、登入、登出與目前帳號查詢。電子郵件註冊的短效引導狀態只保存 scrypt 密碼雜湊與不透明 token 雜湊，完成或逾時後不可再使用；正式 session cookie 為 HttpOnly。`/practice` 與內部診斷入口依正式 session、`learner_access` 與 `question_bank_learners` 決定可用學習者及題庫。帳號回應只提供練習所需的學習者資料，不包含學校或 private asset。
- 自動化測試只用隔離的合成使用者、學習者與測試資料庫；這不改變正式匯入資料的持久性。未驗證電子郵件可在 localhost 或同一 tailnet 的私有 HTTPS 入口登入；本機信箱驗證、密碼重設與角色 PIN 設定／重設的 challenge、API 與介面已完成，實際 SMTP 執行環境與真實投遞尚未設定。Google、LINE 與 Facebook 快速註冊仍缺各供應商 App 設定與真實帳號往返驗收。公開／production HTTPS、公開登入 rate limit、帳號綁定、跨帳號分享、RLS、production GRANT、正式角色授權、物件儲存與資料保存政策仍未完成，也不部署到 Vercel。
- 完整啟動、匯入與驗收方式記錄在[本機 PostgreSQL 操作與診斷](local-practice-pilot.md)。

## 已封閉的 JSON 契約與剩餘資料域

- 前端不得直接引用題目與學習者 fixture。正式帳號、角色、學習者、練習與作答只經由受 session 保護的 API 讀寫 PostgreSQL。
- `data/fixtures` 與 `runtime-data` 只供隔離測試或歷史相容程式使用，不得覆蓋已匯入題目或已建立的帳號、角色、學習者、練習及作答。舊 `/api/v1/bootstrap`、`state`、`reset`、`questions`、`imports` 與 storage-key asset 路徑固定回傳 HTTP `410`，不能在正式主流程重新啟用。
- 歷史 JSON 題目保存科目、年級、學期、版本、章節或課次、單元、主題、知識點、題型、難易度與來源；搬移時需保留原始檔名、頁碼或題號，以及文件、路徑、AI 或人工確認等來源證據。未列入固定欄位的文件項目保存於 `metadata`，不可在搬移時捨棄。
- 歷史 `kind` 只描述作答方式；`typeLabel` 保存來源文件的題型名稱，`sourceAnswer` 保存來源文件原樣的答案文字。複合題以 `parts` 保存每一個小題、選項與答案，搬移時不能把整組題目壓成單一選擇題。
- 歷史題幹、選項、答案與解析使用有序內容區塊；圖片本體在 runtime asset 目錄，JSON 保存檔案鍵值、MIME type、替代文字、尺寸、所屬區域與顯示順序。這些資料只作為未來搬移來源，不再由正式主流程讀寫。
- 正式 PostgreSQL 題目草稿、發布 API 與 `/questions/new/*`、`/questions/drafts/*` 介面已交付。舊 mock `/bank` 仍轉址到 `/questions`，舊 `/api/v1/imports` 固定回 HTTP `410`。現行掃描流程已接入本機 PaddleOCR 與固定本機 Ollama 逐頁拆題；完整文件版面模型、跨頁題組合併與市場級掃描驗收尚未完成。
- 正式切換可沿用 `/api/v1` 路徑，但不能只把 JSON 存取函式換成 SQL 或保留整份 state 覆寫。端點必須依正式資源拆分，從可信 session 建立權限範圍，使用交易、冪等與樂觀鎖定，並只回傳目前角色可見的最小資料；完整對照見 `docs/database-completion-matrix.md`。
