# 管理後台整合介面品質審查

審查日期：2026-10-17
模式：Combined mode（設計與實作合併審查）
狀態：報告完成，等待確認，尚未修正

## 範圍

實際操作管理後台的首頁、帳號、題庫、題目審核、訂閱方案、報表與稽核頁，並與主產品首頁及帳號頁比較。桌面尺寸為 1440 × 900，手機尺寸為 390 × 844。

後台使用隔離資料庫，只有 1 個合成帳號與 0 題，故本次可驗證版面、導航、登入與空資料狀態，不能代表 279 題正式資料下的完整密度與效能。未執行真實新增、刪除、匯入、付款或螢幕閱讀器測試。

## 結論

視覺語言、響應式結構與基本狀態處理大致符合前端；核心阻擋在產品整合，而不是單頁排版。使用者目前無法從正式網址進入後台，登入後也不會返回原管理頁，這兩點會使管理任務在開始前就中斷。

## 發現

### IQ-01｜高｜管理員登入流程在帳號頁中斷

- 狀態：待處理
- 任務：從 `/admin` 進入並完成登入。
- 實際行為：未登入時會帶著 `returnTo=/admin` 前往 `/account`，但帳號頁不讀取該參數；登入成功後仍停留原頁，且畫面只提供前往練習。
- 影響：管理員必須知道並再次手動輸入 `/admin`，新管理員可能判斷後台不存在。
- 建議：用單一、可測試的 redirect helper（導向輔助函式）驗證站內 `returnTo`；登入成功後回到原頁，外部 URL、非管理員與失效 session 必須安全拒絕。
- 驗收：管理員從 `/admin` 開始可一次完成登入並回到後台；一般使用者不能透過 `returnTo` 取得管理權限。

### IQ-02｜高｜正式入口與畫面資料來源不一致

- 狀態：待處理
- 任務：在產品網址管理現有帳號與題目。
- 實際行為：8443 的 `/admin` 回傳 404；獨立後台顯示 1 個帳號與 0 題，主產品資料庫則有 14 個帳號與 279 題。
- 影響：畫面即使可操作，也無法完成管理正式產品資料的目的；使用者可能誤把合成資料當成正式狀態。
- 建議：先完成單一執行環境與資料來源，再公開後台網址；頁尾或系統狀態可顯示環境與資料庫識別，避免測試／正式混淆。
- 驗收：前後台對同一筆帳號與題目顯示一致，且正式網址直接到達後台登入或首頁。

### IQ-03｜中｜手機報表的 30 日趨勢資訊重複且過長

- 狀態：待處理
- 任務：在手機快速判斷近期變化。
- 實際行為：同一趨勢同時以視覺摘要與長資料表呈現，390 px 下需要大量捲動才能到下一區塊。
- 影響：可讀性沒有破版，但主要洞察被完整明細拉長，管理者難以快速掃描。
- 建議：保留無障礙資料表，但預設收合為「查看每日明細」，先顯示摘要、變化值與異常日。
- 驗收：手機首屏後可快速看到下一個報表區塊；展開後仍能取得完整每日資料與鍵盤操作。

## 已檢查但未發現阻擋問題

- 1440 px 與 390 px 均未發現全頁水平溢位。
- 手機版表格會轉成卡片，主要欄位未被截斷。
- 手機導覽選單可展開並到達各管理區。
- 紫色、白色、卡片與表單元件和主產品的品牌方向一致。
- 頁面具備載入、空資料及錯誤狀態，未以空白畫面代替。
- 破壞性操作與敏感欄位在目前可見介面中有區隔，不過仍需在正式資料下做完整操作驗收。
