# 題目總覽與錯題排行榜篩選程式碼共用審查

## 審查摘要

- 呼叫專案：`lerniqa`
- 審查範圍：`app/page.tsx` 的題目總覽與錯題排行榜篩選、兩個排行分頁，以及 `app/globals.css` 的相關版面樣式
- 搜尋範圍：整個 repository；確認篩選 state、選項來源、題目過濾、重設行為、分頁、勾選狀態與既有共用元件
- 既有變更：有。`docs/plan.md` 與 `docs/question-database-design.md` 是工作區既有變更，本次不修改
- 結論：兩個頁面都在篩選同一種 `Question` 資料，但目前只有科目使用共用的 `SubjectFilter`。錯題排行榜缺少題目總覽已有的版本、題型、來源、收藏清單與搜尋，且兩邊各自維護單元選項和過濾條件；應改成同一份篩選資料結構、共用畫面元件及純篩選函式，再由各頁保留自己的資料集合與後續操作。

## 發現項目

### CR-01 題目篩選只有科目共用，其餘欄位與過濾規則分開維護

- 優先程度：高
- 信心：高
- 目標實作：`app/page.tsx` 的 `renderMistakes`、`mistakeSubject`、`mistakeScope`、`mistakeScopeOptions`、`visibleMistakeQuestions` 與 `visibleCommunityMistakeRows`
- 既有或候選實作：`app/page.tsx` 的 `renderQuestionOverview`、`questionSubject` 至 `questionSearch`、各項選項來源、`filteredOverviewQuestions`、`resetQuestionFilters`，以及既有 `SubjectFilter`
- 重疊行為：兩個頁面都依目前學習者、科目與單元篩選 `Question`，條件變更後都要回到第一頁並清除已勾選題目。題目總覽另有版本、題型、來源、收藏清單與關鍵字；錯題排行榜另寫一套科目與單元判斷，個人排行、社群排行及後續練習佇列又各自重複套用條件。
- 影響：使用者在題目總覽能設定的條件，切到錯題排行榜後無法沿用同一種篩選方式。日後新增資料庫欄位或調整條件相依規則時，需要修改多個 predicate(判斷函式)，容易發生欄位、選項與實際結果不同步。
- 建議：建立單一 `QuestionFilters` 資料結構，包含科目、版本、單元、題型、來源、收藏清單與搜尋文字；由共用 `QuestionFilterPanel` 顯示相同欄位，由純函式依傳入的候選題目與收藏清單產生選項並套用條件。題目總覽傳入全部年級題目，錯題排行榜依目前的個人或社群排行傳入候選題目。切換個人與社群排行時保留仍有效的條件，只清除候選集合中已不存在的值。新增收藏清單是題目管理動作，不放入共用篩選元件。
- 預計影響範圍：`app/page.tsx`、新增一個共用題目篩選元件或同等共用模組、`app/globals.css`，以及後續新增的篩選單元測試。現有 `SubjectFilter` 應併入新的共用元件或成為它的內部組件，不保留第二套頁面專用篩選邏輯。
- 驗證方式：以相同條件分別檢查題目總覽、個人錯題排行與社群錯題排行，確認結果都是原候選集合的正確交集；逐項測試科目、版本、單元、題型、來源、收藏清單與搜尋；確認條件改變會回到第一頁並清除隱藏題目的勾選；以桌面與手機寬度操作所有欄位；執行 lint、build 與正式網址驗證。
- 決策事項：收藏清單會依目前登入帳號的清單篩選個人及社群排行中的題目。這是「同題目總覽」的完整一致方案；若社群排行不應受個人收藏影響，需要在施工前排除這一欄。
- 狀態：已驗證

## 不應整併或證據不足

- 題目總覽的新增收藏清單、批次動作，以及錯題排行榜的複習、加入後續練習與排行統計，結果與生命週期不同，不應放進共用篩選元件。
- 個人錯題排行與社群錯題排行使用不同的統計資料，但兩者都持有同一個 `Question`；共用篩選只處理題目欄位，不合併排行計算。
- 目前題目總覽沒有年級與學期控制，年級由目前學習者決定，學期也不是獨立篩選欄位。本次不自行增加畫面上不存在的條件。

## 建議執行順序

- 先建立共用篩選資料結構、選項產生與純篩選函式，補齊條件交集及失效值重設測試。
- 再以共用 `QuestionFilterPanel` 取代題目總覽和錯題排行榜的篩選畫面，保留各頁的分頁、勾選與操作。
- 最後移除舊的 `mistakeSubject`、`mistakeScope` 與重複 predicate，完成桌面、手機、本機 build 及 Vercel production 驗證。
