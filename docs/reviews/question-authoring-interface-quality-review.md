# 新增題目與正式練習一致性審查

## 審查範圍

- 專案：`lerniqa`
- 模式：combined
- 範圍：`/questions/new` 的手動編輯器、草稿格式、正式題目資料表、練習呈現與作答後解答
- 核心使用者：自行建立題目的學生、家長、家教與社會人士
- 核心任務：建立的題目可在正式練習中完整呈現、作答、判分與查看解答，不因再次編輯而遺失內容

## 證據與限制

- 已檢查手動編輯器、草稿轉換、發布寫入、正式練習 renderer(呈現元件)、作答型別與參考答案查詢。
- 現有資料庫可保存題目、小題、選項與解析中的有序文字、圖片、公式、表格及頁面裁切圖。選擇題的正確答案以選項鍵值保存；文字題的可接受答案以文字保存。
- 正式練習可呈現含圖片的選項，並會依選項是否含圖片調整欄數。練習作答值目前只有文字或選項鍵值清單；手寫圖片是另行保存的作答附件，不是可自動判分的答案值。
- 本次沒有使用既有帳號建立或發布測試題，避免改動持久資料。瀏覽器目前沒有可用的登入狀態，因此結論以現有程式與資料契約為主要證據。
- 「提醒」已定義為作答前提示；答案格式說明仍由作答方式產生，作答後內容統一稱為「解答與解析」。

## 結論

手動編輯器目前不符合正式題目的完整能力。資料庫與草稿格式已能表達圖片選項和圖片解析，正式練習也能顯示圖片選項，但手動編輯器只提供文字欄位。載入含圖片的選項或解析後再次編輯，現有轉換還可能把非文字內容捨棄。

「圖片答案」應拆成不同用途處理。圖片選項應由使用者勾選正確選項，正確答案仍保存選項鍵值，才能沿用現有自動判分。圖形解答、作圖結果或答案示意圖應放在「解答與解析」，作答後才顯示。若需求是讓學習者上傳一張圖片作為答案，則需要新增作答方式、附件權限、批改流程與歷程呈現，不能把它混入現有文字答案欄位。

「題幹」是評量設計中的專業名詞，指題目中提出問題、情境或條件的主要內容。它不是錯誤用語，但不適合直接放在面向一般使用者的主要欄位名稱。介面應依使用情境改用「題目內容」、「大題說明」與「小題內容」。

## 待核准修正

### IQ-01｜手動編輯會遺失圖片選項與圖片解析

- 嚴重度：High
- 信心：高
- 根因：正式資料使用有序內容區塊，手動編輯器卻把小題內容、選項與解析縮成單一文字欄位。
- 證據：`ImportOptionDraft.blocks`、`ImportPartDraft.prompt` 與 `ImportPartDraft.explanation` 都接受圖片等內容區塊；`PersistedQuestionFields` 也會呈現選項的 `contentBlocks`。手動編輯器的 `optionText` 會把整個選項改寫成一個文字區塊，`toEditorQuestion` 只取解析中的文字，`toQuestion` 也只把文字寫回解析。
- 使用者後果：透過掃描或 JSON 匯入的圖片選項與圖片解析，打開手動編輯後可能看不到，修改並儲存時可能遺失。使用者也無法直接建立看圖選答案、幾何圖形解答或附圖解析。
- 建議：建立一個共用的「內容編輯器」，由題目內容、小題內容、每個選項、解答與解析共同使用。內容編輯器依資料契約提供文字、圖片、公式、表格與頁面裁切圖，並保存原有順序。新增、刪除或編輯文字時，不得改寫同一位置的其他內容區塊。
- 驗收：手動建立一題四個圖片選項的單選題，勾選正確選項，儲存、重新開啟、預覽、發布與正式練習後，圖片順序和正確答案不變。另建立含圖片解析的文字題，完成作答後可看到圖片解析，作答前不得取得解析內容。
- 狀態：已施工並通過契約、型別、build 與桌面渲染驗證；登入後持久資料 E2E 待隔離帳號

### IQ-02｜缺少可由出題者設定的作答前提示

- 嚴重度：Medium
- 信心：中
- 根因：現有資料只有題目內容、答案與解析，沒有獨立的提示欄位。練習頁目前出現的提示是系統依題型產生的答案格式說明，不能由出題者設定。
- 使用者後果：出題者無法提供分階段提示；若把提示寫進題目內容，學習者無法自行決定是否查看；若寫進解析，又只能在送出答案後看到。
- 建議定義：把「提醒」定義為「作答前提示」。每個可作答小題可有零個或多個有序提示，預設收合，由學習者按「查看提示」後展開。提示不參與判分，也不和作答後的解答與解析共用欄位。提示內容沿用文字、圖片、公式與表格的內容區塊。第一版只需記錄目前展開狀態，不把是否看過提示納入成績；若日後要分析提示使用率，再另定事件與隱私規則。
- 替代解讀：若「提醒」只指「答案請用分號分隔」這類格式說明，應由作答方式自動產生，不應讓出題者重複輸入。若指作答後教學說明，則應命名為「解答與解析」。
- 驗收：同一小題可新增、排序與刪除提示；預覽與正式練習預設不顯示內容，展開後可見，切換小題與返回時不會顯示到其他小題；送出答案前的題目 API 不包含標準答案或解析。
- 狀態：已施工；提示預設收合並逐次展開

### IQ-03｜介面暴露資料庫術語，無法按出題工作完成設定

- 嚴重度：Medium
- 信心：高
- 根因：表單直接呈現 `stableKey`、`parentStableKey`、`answerFieldCount` 與 `gradingPolicy` 的資料結構，欄位名稱也沿用「共用題幹」與「小題題幹」等專業用語。
- 使用者後果：使用者需要先理解資料庫結構，才能建立一般單題或子題。`小題鍵值` 和 `上層小題` 容易被誤認為必填的教學資料；`答案欄位數` 也無法說明它和實際練習畫面的關係。
- 建議：編輯流程改成「題目內容、作答方式、選項與正確答案、作答前提示、解答與解析」。一般單題不顯示小題結構；按下「新增小題」後才出現「大題說明」與依序排列的「小題內容」。穩定鍵值由系統產生，建立巢狀結構時改用「設為第幾題的子題」，並收進進階設定。`答案欄位數` 改為「作答格數」，`判分方式` 改為「如何批改」，並只顯示該作答方式允許的選項。
- 建議用語：

| 現有名稱 | 建議名稱 | 使用時機 |
| --- | --- | --- |
| 共用題幹 | 題目內容 | 一般單題 |
| 共用題幹 | 大題說明 | 含兩個以上小題時 |
| 小題題幹 | 小題內容 | 含小題時 |
| 小題鍵值 | 不顯示 | 由系統產生 |
| 上層小題 | 設為子題 | 只在進階設定顯示 |
| 答案欄位數 | 作答格數 | 文字作答時 |
| 判分方式 | 如何批改 | 依作答方式限制選項 |
| 答案 | 可接受答案 | 文字自動判分時 |
| 解析 | 解答與解析 | 作答後顯示 |

- 驗收：第一次使用者不接觸內部鍵值即可建立一般單題、題組與巢狀子題；預覽使用同一份草稿資料呈現正式練習結果；桌面與手機皆不因進階設定而拉長主要流程。
- 狀態：已施工；內部穩定鍵值已隱藏，子題關係移至進階設定

## 建議施工順序

先建立共用內容編輯器，並修正草稿往返不遺失內容。接著補上作答後的圖片解析資料回傳與呈現。若確認需要作答前提示，再新增提示資料契約、發布流程與練習展開介面。最後收斂欄位名稱、隱藏內部鍵值，並用正式練習預覽完成桌面與手機驗收。

若需求包含「學習者上傳圖片作為答案」，應另立功能範圍。該功能至少需要新的作答模式、private asset(私人資產)授權、檔案格式與大小限制、人工或 AI 輔助批改、結果揭露時機，以及歷程與匯出規則。
