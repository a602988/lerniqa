# 題目篩選介面品質審查報告

## 審查範圍

- 專案：`lerniqa`
- 模式：component
- 範圍：`/questions`、`/mistakes`、`/practice` 的題目篩選元件與難易度比例設定
- 核心使用者：學習者、家長與家教
- 核心任務或契約：三個入口使用同一套可展開題目篩選；開始練習額外提供收藏清單、本輪題數與難易度比例，比例模式啟用時一般難易度不參與選題

## 證據與限制

- 已實際操作：在 Chrome 以 `http://127.0.0.1:3500` 驗收題目總覽、錯題排行榜與開始練習。桌面視窗為 1920 × 902，手機斷點使用 390 × 844。
- 已檢查：展開與收合、鍵盤 Enter 展開、`aria-expanded`、搜尋、收藏清單、一般難易度、比例模式、百分比合計錯誤、開始練習按鈕停用、手機版水平溢出及 Chrome Console。
- 同功能家族對照：三個入口均呼叫 `QuestionFilterPanel`；篩選欄位使用 Keel 的 `FormField`、`NativeSelect`、`Input`、`Checkbox` 與 `Button`。頁面只負責候選資料與開始練習專屬設定。
- 程式證據：共用元件位於 `app/components/question-filter-panel.tsx`；三個呼叫端位於 `app/page.tsx`；比例選題與互斥條件也位於 `app/page.tsx`。
- 自動驗證：`npm run build` 通過；`npm test -- --runInBand` 通過，共驗證 108 題；`git diff --check` 通過。Build 仍會顯示 Keel 文件預覽選用套件缺少的既有警告，未影響本次頁面編譯或操作。
- 未涵蓋：Safari、Firefox、實體觸控裝置、螢幕閱讀器逐項朗讀，以及正式資料庫回傳的極大量篩選選項。

## 結論

本次指定範圍通過 Chrome 驗收。三個入口的展開、收合、欄位名稱與操作來源一致；開始練習能顯示收藏清單及難易度設定。比例模式啟用後，一般難易度選單會停用，百分比合計不是 100% 時，真正開始題目的按鈕會停用。

390 × 844 下篩選區塊沒有水平溢出，欄位維持雙欄排列，科目按鈕維持三欄排列。Chrome Console 沒有應用程式錯誤。本次沒有確認到需要調整的介面品質問題。

## 已檢查但未發現問題

- 題目總覽可透過滑鼠及 Enter 展開篩選，`aria-expanded` 由 `false` 更新為 `true`。
- 錯題排行榜使用相同的篩選元件，包含收藏清單、難易度與搜尋。
- 開始練習啟用比例模式後，一般難易度選單停用並顯示三個百分比欄位。
- 百分比由 100% 改為 110% 時會顯示錯誤，頁首真正開始題目的按鈕停用；恢復 100% 後可重新使用。
- 手機版篩選容器的 `clientWidth` 與 `scrollWidth` 都是 314 px，沒有水平溢出。
- Chrome Console 的錯誤數為 0。

## 確認邊界

本報告只記錄驗收結果，沒有修改 production code。若要擴大到其他瀏覽器、實體裝置或螢幕閱讀器，需另行安排驗收環境。
