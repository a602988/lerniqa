# Lerniqa 管理後台與付費能力審查施工計畫

建立日期：2026-10-17
狀態：施工中；R1、R4 已完成，R2、R3 等待正式帳號授權後驗證
來源：[系統審查](./review.md)、[介面品質審查](./reviews/admin-backoffice-integration-interface-quality-review.md)

## 執行原則

- 先整合管理後台與正式資料，再開發 AI 商品權益，最後才接金流。
- 不以後台舊工作樹覆蓋主分支；所有移植都以最新 `main` 為基準並保留既有前端變更。
- 不使用 seed、reset 或測試 cleanup 改寫正式持久資料。
- 每階段只跑與差異直接相關的驗證；全部 production code 凍結後，才執行完整最終驗收。

## 任務

### R1｜整合前基準與差異凍結

- 狀態：完成
- 角色：架構師、工程師
- 來源：SR-01
- 目標：建立可回溯的整合基準，避免遺失主分支新前端、migration 0013 或後台未提交內容。
- 修改範圍：Git 分支／工作樹、整合清單與交接證據；不改功能行為。
- 動作：記錄兩個工作樹的 commit、未提交檔案與責任範圍；逐檔分類為移植、重寫、捨棄或需人工合併。主工作樹有持續更新且尚未提交的前端內容，因此保留原後台工作樹作為只讀來源，直接把全新的後台模組移植到目前主工作樹；沒有合併會刪除主分支新功能的舊分支內容。
- 完成條件：所有後台差異都有歸屬，無檔案以整批覆蓋方式處理。
- 驗證：`git status`、`git diff --stat`、migration 清單與 hash 核對。
- 依賴：使用者核准審查計畫。
- 風險與回退：保留原後台工作樹；整合失敗時捨棄新的整合工作樹，不動原始兩邊。
