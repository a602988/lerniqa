# 系統管理員與題目異動規劃

狀態：部分可執行

這份文件定義正式帳號、系統管理員及題目異動權限。正式架構中的 Vercel 專案只負責前端介面；登入、授權、資料庫及預設系統管理員都屬於未來的後端服務。現有 `/api/v1` 模擬 API 是過渡用途，不得延用為正式帳號或權限服務。後端部署環境與登入服務尚未選定，因此目前可以先確定資料契約、權限規則與驗證方式，不得把前端示範資料當成正式權限來源。

## 已確認的產品規則

- 系統提供一個不寫入應用程式資料庫的預設系統管理員。此帳號用於首次設定、管理員全部失效時的復原，以及輪替其他系統管理員。
- 只有系統管理員可以授予或移除其他資料庫帳號的系統管理員權限。
- 一般帳號可以修改自己匯入或建立的題目與答案，不得修改其他帳號或系統提供的題目。
- 系統提供的題目只能由系統管理員修改。
- 權限判斷由後端執行。前端是否顯示按鈕或勾選框只影響操作介面，不能作為授權依據。

## 系統邊界

### Vercel 前端

Vercel 只保存公開的前端程式與後端 API（應用程式介面）網址。前端不得保存預設系統管理員、密碼雜湊、MFA（多重要素驗證）密鑰、session（登入工作階段）簽章密鑰、資料庫連線資訊或可授予權限的服務憑證。任何使用 `NEXT_PUBLIC_` 前綴的設定都視為可被瀏覽器讀取，不得放入敏感資料。

### 後端服務

後端負責登入狀態、帳號身分、權限判斷、題目所有權、資料驗證與稽核紀錄。每一次管理員權限異動及題目寫入都要重新檢查目前登入者，不接受前端送來的角色、建立者或系統管理員旗標作為可信依據。

### 資料庫

資料庫保存一般帳號、管理員權限、題目所有權、題目版本及稽核紀錄。預設系統管理員不建立 `User` 資料，也不出現在帳號搜尋、管理員清單或一般報表中。

## 預設系統管理員

預設系統管理員的身分應保存在後端部署環境的 Secret Manager（密鑰管理服務）。若採用外部登入服務，後端只保存該身分不可變的 `subjectId`，不以可能被修改或重複使用的電子郵件判斷。若第一階段必須由後端自行驗證密碼，Secret Manager 至少保存獨立的帳號識別碼、Argon2id 密碼雜湊、MFA 密鑰及 session 簽章密鑰，不能保存明碼密碼。

這個帳號具備以下限制：

- 不提供前端新增、修改、停用或刪除入口；更換身分必須透過後端部署設定完成。
- 不使用公開或共用的預設密碼。正式、測試與本機環境要分別設定不同憑證。
- 登入必須限制嘗試頻率並啟用 MFA。敏感操作需要重新驗證，不只依賴既有 session。
- 稽核紀錄使用固定的系統操作者識別碼，例如 `bootstrap-admin`，但不能把 Secret 內容寫入 log（執行紀錄）。
- 憑證遺失或疑似外洩時，由後端部署權限持有人輪替 Secret、撤銷既有 session，並檢查管理員權限異動紀錄。

## 權限規則

| 操作 | 一般帳號 | 資料庫系統管理員 | 預設系統管理員 |
| --- | --- | --- | --- |
| 修改自己建立的題目與答案 | 允許 | 允許 | 不適用 |
| 修改其他帳號建立的題目 | 拒絕 | 預設拒絕，待另行定義內容管理規則 | 預設拒絕 |
| 修改系統題目 | 拒絕 | 允許 | 允許 |
| 授予或移除系統管理員 | 拒絕 | 允許 | 允許 |
| 修改預設系統管理員 | 拒絕 | 拒絕 | 只能由後端部署設定輪替 |

找不到身分、題目所有權或題目來源時一律拒絕寫入。介面沒有顯示某項功能，不代表後端可以省略相同檢查。

## 資料契約

正式資料庫以 `docs/question-database-design.md` 的資料表為權威來源。實際表名可依選定的 ORM（物件關聯對映工具）調整，但以下語意不得改變。

### `users` 與 `user_roles`

- `users.id` 保存帳號不可變識別碼，不保存系統管理員旗標。
- 每一次系統管理員授權在 `user_roles` 建立 `role=system_admin` 的紀錄，並保存授權者類型、授權帳號與時間。
- 移除權限時填入原授權紀錄的 `revoked_by_type`、`revoked_by_user_id` 與 `revoked_at`，不刪除歷史授權。
- 預設系統管理員授權時使用 `granted_by_type=bootstrap_admin`，`granted_by_user_id` 保持空值。它不是資料庫帳號，不能建立一筆假的 `users` 資料替代。
- 同一帳號與角色只能有一筆尚未撤銷的授權。API 回應中的 `isSystemAdmin` 是由有效 `user_roles` 計算的衍生值，不是可由前端寫入的欄位。

### Question

- `origin`：`system` 或 `account`。
- `owner_user_id`：帳號建立題目時必填；系統題目為 `null`。
- `current_revision_id`：目前顯示的題目版本。

題目匯入時，後端依登入身分寫入 `owner_user_id`，不得接受前端指定其他帳號。一般匯入固定建立 `account` 題目；只有系統管理員使用系統題庫匯入入口時，才能建立 `system` 題目。既有 fixture 搬入正式資料庫時標記為 `system`，不得依題號、來源文字或檔名推測。

### QuestionRevision

題幹、選項、答案、解析與可影響作答結果的欄位每次修改都建立新版本。歷史作答要連結當時的題目版本，避免更正答案後改變舊作答的判定依據。

系統題目的新版本必須由有效系統管理員或預設系統管理員留下審核紀錄，結果寫入 `question_revision_reviews`。被退回的版本保留審核原因與歷史狀態，不得覆寫既有審核紀錄。

既有 fixture 搬移是一次性例外。搬移工具核對內容雜湊、題目筆數、必要欄位與來源後，可將既有系統題目第一版直接發布，並以 `created_by_type=migration` 及 `admin_audit_logs` 保存搬移證據，不建立虛構的管理員或審核紀錄。正式資料庫啟用後建立或修改的系統題目不得使用此例外，仍須由建立者以外的有效系統管理員審核。

### AdminAuditLog

管理員權限異動及系統題目修改至少保存操作者類型、操作者識別碼、目標帳號或題目、操作、異動前後內容、時間、request ID（請求識別碼）及來源 IP。稽核紀錄不得由一般管理介面修改或刪除。

## 後端 API 契約

- 管理員帳號清單需分頁與搜尋，回應可以提供 `isSystemAdmin`，不得回傳密碼雜湊、MFA 密鑰或內部 session 資料。
- 管理員權限異動端點只接受目標帳號與啟用狀態。操作者身分由後端 session 取得，成功寫入權限與稽核紀錄必須在同一個 transaction（資料庫交易）內完成。
- 題目新增與匯入由後端決定 `origin` 與 `ownerUserId`。一般匯入端點不得接受建立系統題目的參數。
- 題目修改端點先載入題目來源與所有者，再依權限表判斷。修改題目、建立版本及寫入稽核紀錄必須在同一個 transaction 內完成。
- 未登入回傳 `401`；已登入但沒有權限回傳 `403`；請求中的題目或帳號不存在回傳 `404`。對外錯誤不回傳 Secret、SQL、內部路徑或 stack trace（堆疊追蹤）。

## 管理介面

帳號管理頁只對系統管理員開放。每個資料庫帳號提供「系統管理員」勾選欄位；操作前顯示權限影響，送出時要求重新驗證，完成後依後端回應更新畫面。前端不能先行永久修改狀態，失敗時要保留原值並說明無法完成的原因。

題目編輯入口依後端回傳的 `canEdit` 顯示。一般帳號只能看到自己題目的編輯操作；系統管理員可以看到系統題目的編輯操作。即使使用者自行呼叫 API，後端仍需套用相同規則。

## 實作順序

### 確認正式環境

- 角色：架構師、安全責任人。
- 輸入：後端部署候選、登入服務候選、Secret Manager、正式網域與資料庫方案。
- 產出：後端與前端的網路邊界、身分來源、session 方式、MFA 方式及 Secret 輪替流程。
- 完成條件：具名責任人確認正式環境的登入服務、後端部署位置與 Secret 管理方式；沒有證據前不得開始正式帳號施工。
- 回滾點：保留現有前端示範登入，不加入假的正式權限。

### 建立帳號與題目資料模型

- 角色：工程師。
- 輸入：已確認的正式環境與本文件的資料契約。
- 產出：migration（資料庫遷移）、資料限制、索引及既有 fixture（初始資料）搬移工具。
- 完成條件：帳號題目一定有所有者，系統題目沒有帳號所有者；歷史作答能連結題目版本；migration 可前進及回滾。
- 驗證：資料庫限制測試、migration 往返測試、fixture 全量搬移與數量核對。
- 回滾點：回滾 migration，不修改原始 fixture。

### 建立登入與集中授權

- 角色：工程師、安全審查員。
- 輸入：登入服務、預設系統管理員 Secret 及資料模型。
- 產出：後端 session、集中權限判斷函式、權限異動 API、題目新增與修改 API、稽核紀錄。
- 完成條件：每一個寫入端點都從可信 session 取得身分並預設拒絕；權限與資源所有權測試涵蓋允許及拒絕案例。
- 驗證：API 整合測試、越權測試、session 撤銷、頻率限制及 Secret 缺失時拒絕啟動。
- 回滾點：停用正式寫入端點，保留只讀 API。

### 串接管理與題目編輯介面

- 角色：前端工程師。
- 輸入：已驗證的正式後端 API。
- 產出：帳號管理頁、管理員勾選流程、題目編輯入口及錯誤狀態。
- 完成條件：前端不保存或推導權限；重新整理後狀態以後端為準；桌面與手機皆能完成管理員異動與可授權的題目修改。
- 驗證：桌面與手機操作、鍵盤與焦點、逾時 session、`401`、`403`、`404` 及寫入失敗回復。
- 回滾點：隱藏管理與編輯入口，不影響題目瀏覽及練習。

### 凍結與最終驗收

- 角色：審查員、優化師、安全審查員、驗收員。
- 輸入：完成的後端、migration、前端與測試。
- 產出：程式審查、安全審查、完整 QA（品質保證）矩陣與正式環境驗收證據。
- 完成條件：一般帳號不能提升權限、不能修改他人或系統題目；系統管理員可以管理資料庫帳號及系統題目；預設系統管理員不出現在資料庫或一般帳號介面；稽核紀錄可追查所有敏感操作。
- 驗證：凍結 production code（正式環境程式碼）後依序執行 Ai Slop Cleaner、Code Review、Security Review 與 UltraQA；任何後三項修正若修改 production code，解除凍結並重新從 Ai Slop Cleaner 開始。
- 回滾點：撤回管理功能與題目寫入 API，保留資料庫備份及稽核證據。

## 尚待確認

- 正式後端部署環境、資料庫及 Secret Manager。
- 正式登入服務，以及預設系統管理員要綁定哪一個不可變身分。
- MFA 使用 passkey、TOTP 或登入服務提供的其他方式。
- 資料庫系統管理員是否可以修改其他帳號建立的題目。現階段規則是拒絕，避免把管理帳號等同內容所有者。
- 系統管理員是否可以移除自己的管理員權限。建議介面禁止自行移除，改由另一位系統管理員處理。

## 安全依據

- [OWASP Authorization Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)：預設拒絕，且每次請求都重新驗證權限。
- [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)：密碼不可保存明碼，新的密碼驗證優先使用 Argon2id。
- [OWASP Multifactor Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)：高權限帳號需啟用 MFA，敏感操作應要求重新驗證。
