# 題目篩選共用調整計畫

## 狀態

已完成並部署至 Vercel production。`docs/reviews/question-filter-code-reuse-review.md` 的 `CR-01` 已於 2026-10-15 核准，最終驗證證據記錄於該報告。

## 範圍

題目總覽、個人錯題排行與社群錯題排行使用同一份篩選資料結構、選項來源、條件判斷及篩選面板。錯題清單沿用題目總覽的緊湊表格版型，保留排行與錯題統計，不改變作答紀錄、排行計算或持久化格式。

## 執行批次

### 共用篩選契約

- 角色：前端工程師
- 輸入：`Question`、目前學習者的收藏清單、頁面候選題目及既有篩選 state
- 產出：共用 `QuestionFilters`、選項產生函式、純篩選函式及 `QuestionFilterPanel`
- 完成條件：科目、版本、單元、題型、來源、收藏清單與搜尋只保留一套判斷；題目總覽與錯題英雄榜都從共用入口取得結果
- 驗證：逐項套用條件，確認三個清單得到候選題目的正確交集；條件失效時回復為「全部」
- 依賴：`CR-01` 核准
- 回滾點：移除新增共用檔案並恢復 `app/page.tsx` 原本的頁面內篩選

### 錯題清單版面

- 角色：前端工程師
- 輸入：題目總覽表格版型、個人及社群錯題欄位
- 產出：與題目總覽一致的緊湊錯題表格，個人排行顯示排名、題目、科目／單元、最後測驗、錯誤次數與操作；社群排行顯示排名、題目、科目／單元、作答次數、錯誤次數與錯誤率
- 完成條件：列高不被操作按鈕或空白撐高；手機改為可讀卡片排列；選取、分頁與既有操作仍可用
- 驗證：桌面、平板及手機實際渲染，確認無水平溢位、欄位對齊且互動可操作
- 依賴：共用篩選契約
- 回滾點：還原錯題表格 JSX 與相關 CSS

### 審查與驗收

- 角色：審查員、優化師、安全審查員、驗收員
- 輸入：全部 production code 差異與核准範圍
- 產出：確認沒有第二套篩選 predicate、舊 state 或無效樣式；確認未改變權限、資料格式與排行計算
- 完成條件：lint、題庫測試、build、桌面與手機操作驗證通過；`CR-01` 更新為 `已驗證`
- 驗證：重新搜尋所有題目篩選呼叫端，執行 `npm run lint`、`npm test`、`npm run build` 與瀏覽器驗證；部署後確認 production
- 依賴：前兩批完成並凍結 production code
- 回滾點：回到本次調整前的 Git commit

## 文件同步檢查

本次不修改資料模型、API、權限或持久化格式。正式規劃文件不需變更；本文件記錄實作與驗證結果，審查報告記錄 `CR-01` 狀態。
