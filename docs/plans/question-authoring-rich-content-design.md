# 題目內容編輯與作答前提示設計

## 問題

正式題目使用有序內容區塊保存文字、圖片、公式、表格與頁面裁切圖，但手動編輯器把小題、選項與解析轉成單一文字欄位。含圖片的草稿再次儲存時會遺失內容。正式練習也沒有出題者可設定的作答前提示，作答後的解析只回傳合併文字，無法呈現圖片。

## 使用方式

手動新增題目先開啟範本選擇。範本清單包含單選題、圖片選擇題、複選題、是非題、填空題、多格填答題、簡答題，以及題組與子題。使用者點選範本後，右側以正式練習元件呈現題目與作答區，並可查看範本答案及解析。按下「使用這個範本」後，系統才建立可編輯草稿。

範本內容是自行編寫的可作答示例，不引用正式題庫或教材原文。只有題組與子題示例使用結構化表格，其他範本使用一般文字題，讓使用者看見表格是可選內容。圖片選擇題在範本預覽使用版本管理內的四張示例圖；套用範本時不把示例圖寫入草稿，草稿只保留圖片位置，等使用者上傳自己的圖片。

每一題都顯示目前推導出的範本名稱。更換範本時保留題目內容、分類及匯入追溯資料，只重建小題、作答方式、選項、答案、提示與解析。介面必須先說明這個影響，避免使用者以為更換範本只會改名稱。

使用者在「題目內容」、「小題內容」、每個選項、「作答前提示」與「解答與解析」中加入有序內容。每個位置使用同一個內容編輯器，可以新增文字、圖片、公式與表格，也可以調整順序或移除內容。

手動新增與匯入後校對使用同一個單題工作區。畫面一次只呈現目前題目，頂端顯示題號、總題數與進度，並提供上一題、下一題與新增下一題。新增範本後直接切換到新題；刪除目前題目後停留在仍存在的相鄰題目。

選擇題以勾選選項決定正確答案。選項本身可以只有圖片。文字題的「可接受答案」仍只保存文字。圖片式解答放在「解答與解析」，不參與自動判分。

每個小題可以有多個作答前提示。編輯器將「解答與解析」排在提示之前；沒有提示時只顯示小型「新增提示」按鈕，有提示時才顯示提示標題與內容。題目範本不預先建立示範提示，只有使用者主動新增或來源明確提供時才建立。練習畫面預設只顯示「查看提示」，學習者逐一展開後才看到內容。提示不包含標準答案，也不改變分數。

## 資料形狀

`ImportPartDraft` 增加必填的 `hints: ImportContentBlock[][]`。草稿邊界仍接受沒有 `hints` 的舊版 v2 資料，解析後一律轉成空清單。內部程式只處理完整形狀。

`question_content_blocks.placement` 增加 `hint`，並新增可為空的 `hint_index`。`hint` 區塊必須連到小題、不得連到選項，而且必須有非負 `hint_index`；其他位置的 `hint_index` 必須為空。同一個 `hint_index` 內使用既有 `position` 排列內容，不另建第二套內容表。

正式練習的小題增加 `hints`，每個提示包含 `position` 與 `blocks`。題目查詢只公開提示、題目內容與選項，不公開答案或解析。參考答案在原有揭露條件成立後才回傳 `explanationBlocks`。

## 設計決定

採用現有內容區塊加上 `hint_index`。它讓題目、小題、選項、提示與解析共用內容型別、資產驗證與呈現元件。編輯器只需維護一種內容資料，不需要在文字欄位與圖片陣列之間反覆轉換。

題目範本是編題輔助，不是新的正式題型欄位。所有範本由同一份型別化清單產生既有 `ImportQuestionDraft`；正式題型仍依小題的作答方式與結構推導。拍照、PDF 與格式匯入的題目也依相同規則顯示最接近的範本，使用者可在校對時更換。

來源題號與來源頁碼只用於匯入追溯。手動新增介面不顯示這兩個欄位；拍照與 PDF 由系統保存頁碼，格式匯入可提供選填值。掃描影像版本依系統保存的頁面關聯切換，不要求使用者輸入頁碼。

介面不顯示 `stableKey`。系統建立小題時產生不重複的鍵值；只有需要巢狀子題時，才在進階設定顯示「設為子題」。一般單題顯示「題目內容」，兩個以上小題時改為「大題說明」與「小題內容」。

## 接受的取捨

- 提示重新排序會改變 `hint_index`。題目版本發布後不可原地修改，因此不需要為草稿中的提示建立長期識別碼。
- 第一版不記錄學習者是否查看提示。若日後要分析提示使用率，需另外定義事件、保存期間與權限。
- 學習者上傳圖片作答不在這項修改內。它需要新的作答方式、private asset(私人資產)規則與批改流程。

## 未採用方案

- 把提示寫進題目內容：資料最少，但無法預設收合，也無法區分題目條件與提示。
- 建立 `question_hints` 與另一套提示內容表：提示身分較明確，但會複製內容區塊、資產與排序規則，呼叫端仍要合併兩種內容型別。
- 把第一個內容區塊當成提示容器：不需要 migration，但會讓文字或圖片同時負責內容與分組，移動區塊時容易破壞提示邊界。

## 第一個施工步驟

先擴充草稿契約與資料庫限制，並用契約測試和 migration 往返測試固定資料形狀，再修改編輯器與練習畫面。
