# 介面品質調整計畫

## 核准範圍

- `docs/reviews/home-dashboard-interface-quality-review.md`：`IQ-01` 至 `IQ-15`。
- 核准依據：使用者原始要求已授權在設計完成後直接修正介面不足；`IQ-08` 與 `IQ-15` 另對應使用者要求建立並統一原創品牌 icon。第二輪只在開發者完成訊號出現後處理。

## 任務

### 合併專注練習標題並釋放手寫空間

- 解決問題：使用者提供的練習截圖中，外層練習標題與題目卡片標頭重複占用高度，送出操作又被手寫板推到兩欄下方，導致 1280×800 出現不必要的頁面捲軸。
- 影響位置：`app/page.tsx` 的專注練習標題與題目卡片，及 `app/globals.css` 的練習雙欄配置。
- 預期行為：練習名稱、學習者、題號、題型、難度、進度與關閉操作集中在單一標題列；桌面版送出操作位於題目欄底部，手寫板保留主要高度；手機版仍依題目、手寫板、送出操作排列。
- 驗證方式：以 1280×800 完成單題練習，確認標題不重複、手寫板與送出操作可在同一畫面使用；再檢查 390 px 手機版的閱讀順序與水平溢位。
- 版本影響：patch
- 回退方式：恢復 `QuestionFlow` 內層標頭及原本的全寬送出列，不影響練習狀態與作答資料。
- 狀態：已完成並驗證

### 修正平板橫向左側導覽間距

- 解決問題：使用者提供的 1280×800 截圖中，左側導覽項目過密，學習者設定與底部提示卡直接相連。
- 影響位置：`app/globals.css` 的左側導覽與學習者設定間距。
- 預期行為：導覽項目維持一致的垂直節奏；即使畫面高度不足，自動分配空間縮為 0，學習者設定與提示卡之間仍保留 24 px。
- 驗證方式：以 1280×800 重現設定頁，量測導覽項目及設定按鈕與提示卡間距；再檢查 390 px 手機與 1440 px 桌面版無水平溢位或新遮擋。
- 版本影響：patch
- 回退方式：只撤回 `.sidebar-nav` 與 `.sidebar-settings` 的間距規則。
- 狀態：已完成並驗證

### 降級無資料依據的考試次別，改用真實單元條件

- 解決問題：`IQ-01`
- 影響位置：`app/page.tsx` 的練習範圍選項、篩選條件、提示與摘要，以及 `README.md` 的現況說明。
- 預期行為：不替既有題目虛構考試次別；次別只作評量名稱，介面根據題目已具備的科目與單元動態產生練習範圍。使用者切換後，題數、摘要與實際題目使用同一結果；沒有題目的組合顯示誠實空狀態。
- 驗證方式：切換年級、科目與所有可選單元，核對題數、摘要及開始後題目；確認介面不再宣稱支援尚未建立資料模型的考試次別。
- 版本影響：patch
- 回退方式：只撤回新增的題目範圍欄位與篩選條件，不動原題幹、答案或既有紀錄格式。
- 狀態：已完成並驗證

### 建立穩定的練習 session 與完成結果

- 解決問題：`IQ-02`、`IQ-03`
- 影響位置：`app/page.tsx` 的練習／錯題題目佇列、作答紀錄、下一題、結果頁及首頁累積統計。
- 預期行為：開始練習或錯題複習時固定本輪題目；答案送出後保留回饋至使用者前進；最後一題後顯示本輪題數、答對、待複習與明確下一步；首頁累積資料不再標成「本次」。
- 驗證方式：完整答完一般練習；製造一筆錯題後在錯題複習答對；確認回饋、完成頁、本輪統計和重新進入錯題清單皆正確。
- 版本影響：patch
- 依賴：考試範圍篩選先建立正確題目集合。
- 回退方式：撤回 session/result state 與結果畫面，保留既有 localStorage 資料格式。
- 狀態：已完成並驗證

### 提升品牌細節、資訊層級與手機操作品質

- 解決問題：`IQ-04`、`IQ-05`、`IQ-07`
- 影響位置：`app/globals.css`、`app/layout.tsx`、`app/page.tsx` 的語意顏色、focus-visible、導覽狀態、主內容排版、手機資訊順序與控制尺寸。
- 預期行為：次要文字達到正常字級可讀對比；導覽目前狀態可由視覺與輔助科技感知；所有主要鍵盤焦點清楚；手機控制具有舒適觸控範圍，核心練習安排在前，桌機三欄品牌方向保持一致並改善細節精緻度。
- 驗證方式：量測代表性文字對比；全頁鍵盤操作；320、390、768、1440、1920 px 截圖與 overflow／尺寸檢查；檢查一般、hover、focus、disabled、feedback、empty、result 狀態。
- 版本影響：patch
- 回退方式：分別撤回語意 token、導航語意與響應式 class，保留功能修正。
- 狀態：已完成並驗證

### 修正設定對話框焦點還原

- 解決問題：`IQ-06`
- 影響位置：`app/page.tsx` 的 Keel `Dialog` 組合。
- 預期行為：Escape、關閉圖示及完成按鈕關閉後都回到「學習者設定」觸發按鈕。
- 驗證方式：三種關閉路徑逐一檢查 `document.activeElement` 與後續 Tab 順序。
- 版本影響：patch
- 回退方式：撤回 `DialogTrigger`／顯式焦點契約，保留其他調整。
- 狀態：已完成並驗證

### 建立原創品牌標誌與小尺寸資產

- 解決問題：`IQ-08`
- 影響位置：`app/components/lerniqa-mark.tsx`、`app/page.tsx` 品牌列、`app/layout.tsx` metadata 與 `public/` 品牌資產。
- 預期行為：不再使用通用畢業帽；同一套原創幾何能用於 44 px 頁首、SVG favicon、32 px ICO 與 180 px Apple icon，並保留既有 Lerniqa 名稱與合理品牌色。
- 驗證方式：Chrome 桌機／手機截圖、16／32 px 點陣預覽、HTML metadata、三個資產的 HTTP status／MIME，以及原畢業帽是否從 DOM 移除。
- 版本影響：patch
- 回退方式：撤回品牌元件與 metadata，功能圖示及其他介面調整不受影響。
- 狀態：已完成並驗證

### 穩定第二輪資料、流程與可及性狀態

- 解決問題：`IQ-09` 至 `IQ-14`
- 影響位置：`app/page.tsx`、`app/lib/demo-data.ts`、`app/components/handwriting-pad.tsx`、`app/globals.css`。
- 預期行為：篩選與題數一致；session 不會被靜默清除或記到錯誤學習者；時長來自真實題目開始時間；純手寫可用鍵盤完成並標成待檢視；相近題、匯入與統計不誇大示範能力；舊資料可安全遷移，無效資料不被靜默覆寫；手機與平板維持 44 px 觸控目標及可靠焦點。
- 驗證方式：Chrome 完成全部作答、逐題檢核、純手寫、錯題／後續題與離開 session；390、768、1440 px 回歸；typecheck、lint、build、console 與 `git diff --check`。
- 版本影響：patch
- 回退方式：依狀態模型、手寫替代輸入、文案與響應式樣式分組撤回；不動開發者完成前的其他版面。
- 狀態：已完成並驗證；資料遷移仍缺自動化測試

## 驗證紀錄

- 專注練習標題：本機與 Vercel production 均在 1280×620 可視區域驗證；文件尺寸等於 viewport，無水平或垂直頁面捲軸，且手寫板維持 384 px 高。390 px 手機版無水平溢位，順序為題目、手寫板、送出操作。
- 左側導覽間距：1280×800 下導覽項目與設定入口間距為 8 px，設定入口與提示卡為 24 px；390、1440 px 無水平溢位。Vercel production 已用相同尺寸複驗。
- `npm run lint`：通過。
- `npm run build`：通過；Keel 未使用文件預覽功能仍顯示 optional dependency warning，不阻斷首頁建置。
- `git diff --check`：通過。
- Google Chrome：一般練習、結果、錯題回饋、純手寫鍵盤替代、待檢視排除於錯題、後續相近題、空白狀態、離開防誤觸、Dialog 焦點與學習者資料隔離已完成實際操作。
- 響應式：320、390、768、1920 px 無水平溢位；可見控制最小高度 44 px；1920 px 內容寬度封頂 1440 px。
- 品牌：Learning Card 標誌於 16、32、44、180 px 檢查可辨識；SVG、ICO、Apple PNG 由本機 production server 以正確 MIME 回傳 200。
- 截圖：修改前後桌機／手機，以及手機結果與錯題回饋均保存在 `docs/reviews/assets/`。
- 預覽：本機 `http://127.0.0.1:3400/`；未部署至 Vercel。原開發程序持續使用 `.next`，因此 production build 驗證後不另長駐 3300。
