# 考試模擬功能規劃

狀態：規劃草案，尚未實作。本文定義產品行為、資料邊界、實作階段及驗收條件。待「產品待確認事項」定案後，需同步更新 `docs/PRODUCT_SPEC.md`、`docs/question-database-design.md`、`docs/ROADMAP.md`、migration 說明及測試文件，再開始施工。

## 目標

使用者可在既有 `/practice` 流程中，為一位學習者建立單一科目的模擬考。使用者可從多種題目來源組成候選池，設定各題型的題數與難易度，套用作答歷史及相同／相近題規則，並設定整題、小題或答案格的配分。系統在組卷前顯示可用題數與缺口，組卷後固定題目版本、順序、規則快照及總分。

本功能沿用現有學習本、發布版本、排程及練習 session。它不建立另一套單科首頁、替代 `/practice` 的產品流程或只存在瀏覽器的臨時計畫。

## 不在首階段範圍

- 不自動產生新題目，也不使用未審核的 AI 相似度補足題數。
- 不因題數不足而偷偷放寬科目、教材版本、冊次、單元或來源條件。
- 不把「同題型」直接當成「相同題」或「相近題」。
- 不從 `score` 模式的總分反推出單題對錯。
- 不在沒有逐答案格標準答案及判分結果的情況下宣稱支援逐格自動判分。

## 名詞與資料邊界

| 名詞 | 定義 |
| --- | --- |
| 模擬考設定 | 可編輯的專用組卷藍圖。它由現有學習本版本引用，沿用既有分享、排程及導航。 |
| 發布版本 | 一份不可變的設定快照。保存科目、候選池、配額、歷史規則及計分規則。 |
| 試卷 | 系統依發布版本選出的固定題目、小題、答案格、題目 revision、順序及配分。 |
| 題型配額列 | 一個標準題型或核准的細題型，以及該列需要的基礎、中等、進階題數。 |
| 已作答 | 學習者對該題送出過可持久辨識的作答或 `score` 收據。只開啟或看到題目不算已作答。 |
| 曾答錯 | `instant` 或已完成的 `complete` 作答中，至少一次保存的結果為錯誤。`score` 不保存單題結果，因此不參與此判定。 |
| 目前錯題 | 最新可揭露結果仍為錯誤，且錯題佇列尚未解決的題目或小題。 |
| 相同模板 | 題目屬於已確認的 `question_template`。這代表題幹骨架與解題方式相同。 |
| 相近題 | 題目屬於已確認的 `question_similarity_group`。未核准候選不參與組卷。 |
| 同題型 | 題目的標準 `question_type` 相同。這是分類條件，不等於相同模板或相近題。 |
| 計分單位 | 一次配分所對應的整題、可獨立判分小題或答案格。 |

## 使用流程

1. 使用者從 `/practice` 建立學習本，選擇「模擬考」。
2. 使用者先選一個科目。科目確定後，介面只顯示該科目的版本、冊次、單元、來源、題型、難易度及來源專屬欄位。
3. 使用者設定候選池。來源可複選，同一欄位內使用 OR，不同欄位之間使用 AND。
4. 使用者加入題型配額列，設定每個題型需要的基礎、中等及進階題數。
5. 使用者設定作答歷史及相同／相近題規則。
6. 使用者設定計分方式與目標總分。系統即時計算題數、計分單位數及預估總分。
7. 系統執行「試組卷」。畫面顯示每一配額列的候選數、排除數、保留錯題數、缺少數量及規則命中原因。
8. 若所有嚴格條件都能滿足，使用者發布版本。系統在同一交易中固定試卷內容與配分。
9. 使用者可立即開始、另行排程或分享學習本。已建立的排程與 session 固定引用當時的發布版本，不跟隨後續修改。

## 設定結構

### 基本設定

- 模擬考名稱。
- 學習者。
- 單一科目。
- 答案揭露方式。首階段使用交卷後揭露的 `complete`；是否開放 `instant` 另行確認。現有 `score` 是隱私導向的無逐題明細模式，不直接當成百分制考卷模式。
- 目標總分。預設為 100 分，可設定為其他正數。
- 配分最小單位。建議首階段固定為 0.5 分。
- 全卷難易度預設比例。包含基礎、中等及進階，三者合計必須為 100%。
- 題目排序方式。可選隨機排序或依題型配額列排序；組卷後固定實際順序。

### 候選池

候選池沿用共用題庫篩選契約，至少包含下列維度：

- 年級、學期、出版社版本、冊次及單元。
- 題目來源，可同時選取多個來源。
- 主題、知識點、難易度、標準題型及來源細題型。
- 來源專屬欄位，例如出處、認知向度、知識向度、課名、年份或梯次。
- 收藏清單及建立者。是否在首階段開放，列入產品待確認事項。

科目不是一般複選條件。每份模擬考必須且只能保存一個 `subject_id`。前端的篩選選項由伺服器依該科目及學習者可存取題庫產生，不在前端維護另一份固定來源清單。

### 題型與難易度配額

每一列包含下列設定：

- 標準題型，或標準題型加已保存的來源細題型。
- 該列小計題數。
- 難易度設定方式，可選「直接填題數」或「依百分比分配」。
- 直接填題數時，設定基礎、中等及進階題數，三者合計必須等於該列小計。
- 依百分比分配時，設定基礎、中等及進階百分比，三者合計必須為 100%。該列可沿用全卷比例，也可自行覆寫。
- 選填的來源限制。空值表示沿用整份試卷的候選池。
- 計分方式。可沿用全卷預設，也可覆寫該列。

系統在試組卷前把百分比換算成整數題數。每格先取 `該列題數 × 難易度百分比` 的整數部分，再依小數餘數由大到小分配剩餘題數。餘數相同時依基礎、中等、進階的固定順序處理。因此同一份設定每次都會得到相同的整數配額。例如某題型共 7 題，比例為 30%、50%、20%，換算結果為基礎 2 題、中等 4 題、進階 1 題。

試組卷畫面要同時顯示使用者輸入的百分比、換算後題數及實際選入題數。發布版本保存原始百分比及解析後整數配額，避免日後因換算規則改變而無法重現舊試卷。

同一題只能滿足一個配額格。題目可能同時符合多列，相同模板或相近題限制也可能讓不同配額格互相競爭。系統要以全卷約束求解，不可逐列貪婪選題後就宣告不足。多個可行解之間使用試卷隨機種子及穩定排序決定結果，並在組卷追溯資料中記錄分配原因。

全卷難易度百分比是各題型配額列的預設值，不是另一套獨立配額。某一列覆寫比例後，以該列比例為準。系統以所有題型列換算後的整數題數加總，顯示整份試卷最終的實際難易度百分比；因整數換算產生的微小差異不視為錯誤。

## 作答歷史規則

歷史規則不使用多個可能互相矛盾的核取方塊。設定分成「保留題目」與「排除題目」，並使用固定優先序。

### 保留錯題

使用者可選擇下列一種規則：

- 不特別保留錯題。
- 保留目前錯題。
- 保留曾答錯題目。

使用者可設定保留題數或各題型配額列內的保留題數。保留錯題仍必須符合科目、候選池、題型及難易度條件。保留不是額外增加題數，而是占用原本的配額。

### 排除精確題目

使用者可選擇下列一種規則：

- 不排除已作答題目。
- 排除已作答題目，但保留規則選中的錯題可例外納入。

判定使用穩定的 `question_id`，不只比對舊 revision。`instant`、已完成的 `complete` 及 `score` 收據都可證明精確題目已作答。進行中但未送出的題目、已放棄 session 中未送出的題目及只有畫面曝光的題目不算已作答。

### 排除已見關係題

使用者可分別啟用下列規則：

- 排除曾作答題目的已確認相同模板成員。
- 排除曾作答題目的已確認相近題群組成員。

標準題型只用於配額與候選篩選，不作為「已見相似題」的排除依據。共同關鍵字、主題或知識點也不在首階段作為排除依據，因為它們只能表示內容相關，不能單獨證明題目相似。

### 規則優先序

系統依下列順序處理每個配額格：

1. 建立符合科目、權限、發布狀態、候選池、題型及難易度的集合。
2. 先選入符合「保留錯題」的候選，直到達到保留題數。
3. 對其餘候選套用精確題目排除。
4. 套用相同模板及相近題排除。
5. 依隨機種子及穩定次排序選到配額數量。

每一道選入或排除的題目都保存規則代碼及所引用的作答、模板或相近題群組識別碼。介面只顯示必要摘要，完整證據供稽核及重現組卷結果。

## 題數不足與遞補

預設使用嚴格模式。任一配額格不足時，系統不發布試卷，並顯示缺少的題型、難易度、所需題數、可用題數及各排除規則造成的數量。

求解器必須區分「條件確實無解」與「在計算上限內未完成」。後者回傳 `solver_limit` 類型的明確結果，不得當成題庫不足。

未來可增加「核准遞補」模式，但每一層都必須由使用者明確開啟。建議遞補順序如下：

1. 保持題型及來源不變，改用相鄰難度。
2. 保持題型及難度不變，放寬該列的來源限制到全卷來源池。
3. 允許已作答但最近結果不是答對的精確題目。

系統不得跨科目、跨未選教材範圍、使用未確認相似關係，或忽略存取權限。每一次遞補都要保存原缺口、使用的層級及選入原因。

## 計分規則

### 計分層級

全卷預設計分方式可選：

- 每題計分。每道題是一個計分單位。
- 每小題計分。每個可獨立判分的 `question_part` 是一個計分單位。
- 每答案格計分。每個正式答案格是一個計分單位。

題型配額列可覆寫全卷預設。使用者也可在試組卷後手動調整個別計分單位。組卷發布後，配分與題目 revision 一起固定，不因題目後續修改而改變。

目前 schema 只有 `answer_field_count`，沒有逐格答案、逐格判分結果或逐格識別碼。因此首階段可以顯示逐格配分計畫，但只有具備正式逐格答案與判分資料的題型才能自動計算逐格得分。其他逐格題必須使用人工評分，或在補齊逐格資料模型前改用每小題計分。

### 自動加總至目標總分

自動配分使用最大餘數法，結果可重現：

1. 系統列出所有計分單位，並套用使用者設定的權重。未設定權重時，每個單位權重為 1。
2. 系統以 `目標總分 × 單位權重 ÷ 權重總和` 算出原始分數。
3. 每個原始分數先向下取到配分最小單位。
4. 系統把剩餘分數依小數餘數由大到小分配。餘數相同時，依題型配額列、題目位置、計分單位位置排序。
5. 系統驗證所有分數大於 0，且加總精確等於目標總分。

若計分單位數乘以最小配分單位大於目標總分，自動配分無解。系統必須要求使用者減少計分單位、降低最小配分單位或改用較高層級計分，不得產生 0 分題。

### 得分與待評分

- 自動判分單位可在送出後計算得分。
- `pending` 或人工評分單位在完成評分前不計入已取得分數，並另顯示待評分配分。
- 多選題是否提供部分分數不能從現有答對／答錯結果推定。首階段預設整個計分單位全對才得分。
- `score` 模式可保存試卷總分及彙總，但仍不得保存或揭露其既有隱私契約禁止的逐題答案與判定。若產品要求重開後顯示逐題得分，必須另行修改資料保存政策及 `score` 契約。

## 組卷演算法契約

組卷必須在伺服器端執行，並在同一個可重試交易中完成下列工作：

1. 驗證帳號對學習者的存取權及建立計畫權限。
2. 鎖定模擬考設定的目前版本。
3. 解析版本化的候選池及歷史規則。
4. 查詢發布中的目前題目 revision，並套用學習者可使用的題庫範圍。
5. 依配額格建立候選與排除證據。
6. 使用伺服器產生並保存的隨機種子完成選題及排序。
7. 建立固定試卷、題目、小題或答案格、配分及選入原因。
8. 驗證題數、配額及總分。
9. 發布不可變版本並提交交易。

相同設定版本、相同候選資料版本、相同歷史截點及相同隨機種子必須產生相同結果。重新產生試卷要建立新版本，不覆寫已發布試卷。

## 建議資料模型

下列名稱是規劃名稱，實作前需在正式資料設計文件中定案。

| 資料 | 用途 |
| --- | --- |
| `practice_plan_revisions.settings_snapshot` | 保存對專用模擬考藍圖版本的引用及顯示快照，不把完整可查詢契約只塞進 JSON。 |
| `exam_blueprint_revisions` | 保存單一科目、候選池、歷史規則、計分預設、求解器版本及隨機策略。發布後不可變。 |
| `exam_blueprint_sections` | 保存題型配額列、順序、題型、來源細題型及計分覆寫。 |
| `exam_blueprint_quotas` | 保存每一配額列的難易度設定方式、原始百分比、解析後需求題數及錯題保留題數。 |
| `exam_papers` | 保存生成狀態、設定版本、歷史截點、隨機種子、目標總分、配分最小單位及總分驗證結果。 |
| `exam_paper_items` | 固定題目、revision、選定小題、位置、命中配額格及選入原因。可評估是否擴充既有 `practice_plan_revision_items`，避免雙重題目清單。 |
| `exam_score_units` | 保存整題、小題或答案格計分單位、位置、滿分及判分方式。 |
| `exam_selection_evidence` | 保存選入、排除、遞補規則及其作答、模板、相近題群組證據。 |
| `question_answer_fields` | 若要正式支援逐格判分，保存穩定答案格識別碼、順序及其所屬小題。 |
| `answer_field_results` | 若要正式支援逐格自動或人工判分，保存每格結果及審核來源。 |

模擬考藍圖與固定試卷需要專用的不變量，但要由現有 `practice_plans` 及 `practice_plan_revisions` 引用，並沿用 `practice_schedules`、分享訂閱及 `/practice` 導航。固定試卷再連到 `practice_sessions` 的考試執行類型。不要建立平行且互不相容的分享、排程、學習者或作答系統。

`learner_question_stats` 及 `learner_part_stats` 目前不能直接假設為即時權威資料。若 runtime 尚未維護這些讀取模型，首階段應從不可變作答、已完成 session 及 `score` 收據查詢，或先完成 outbox worker、重建及 freshness 契約。

## API 邊界

建議提供下列伺服器能力：

- 儲存及更新模擬考草稿。
- 依草稿取得可用篩選選項。
- 執行試組卷，回傳配額格統計、排除統計、缺口及配分預覽，不建立可作答 session。
- 發布版本並原子建立固定試卷。
- 從固定試卷建立或恢復 session。
- 取得試卷結果、已取得分數、待評分分數及最終總分。

試組卷及發布都使用冪等鍵。發布端點必須比對草稿 `lock_version`、候選池資料版本及歷史截點；資料已改變時回傳衝突，要求重新試組卷，不默默換題。

## 權限與隱私

- 只有對學習者具有 `can_create_plans` 的帳號可建立、發布、排程或分享模擬考。
- 作答結果及試卷得分沿用 `can_view_results`。
- 人工評分沿用 `can_review_answers`。
- 分享學習本不授予其他學習者資料或作答歷史權限。收件者領取後，以自己的學習者歷史重新組卷，不沿用分享者的固定試卷。
- 系統不得在缺口統計中洩漏使用者無權查看的題目內容或其他學習者結果。

## 實作階段

### 第一階段：規格與資料基礎

- 定案本文的產品待確認事項。
- 修正受影響正式文件中的衝突與過時狀態。
- 新增模擬考設定、配額、固定試卷、計分單位及選題證據 schema。
- 建立唯讀候選查詢及試組卷 API。
- 建立從正式作答與 `score` 收據判定「已作答」的查詢契約。

### 第二階段：組卷與整題／小題計分

- 在既有學習本介面加入模擬考設定。
- 支援多來源候選池、題型乘難易度配額、錯題保留及已作答排除。
- 支援全卷難易度百分比、各題型比例覆寫及確定性的整數題數換算。
- 支援已確認相同模板及相近題群組排除。
- 支援每題及每小題配分、自動加總至目標總分、固定試卷與 session。
- 完成嚴格缺口提示、組卷證據及重現測試。

### 第三階段：逐格計分與人工評分

- 建立穩定答案格及逐格結果資料模型。
- 讓支援的題型保存逐格標準答案及判分規則。
- 支援逐格自動配分、人工評分、待評分分數及改判稽核。

### 第四階段：核准遞補與成效分析

- 增加使用者明確開啟的遞補層級。
- 增加試卷難度、來源、題型及得分分布報表。
- 在 confirmed 關係有足夠覆蓋後，評估相同模板及相近題曝光控制的成效。

## 驗收條件

### 規則與資料

- 每份試卷恰好一個科目，所有題目都屬於該科目及學習者可存取題庫。
- 同一題不重複占用多個配額格。
- 全卷存在可行配置時，不得因逐格貪婪選題而誤報不足；計算超限與真正無解必須分開回報。
- 題型及難易度數量完全符合設定；嚴格模式不足時不發布。
- 全卷及各題型列的難易度百分比都必須合計 100%，發布版本同時保存原始百分比及解析後題數。
- 保留錯題先占配額，已作答排除只作用於其餘候選。
- 只有已確認模板及相近題群組可參與關係排除。
- 試卷固定題目 revision、順序、配分、隨機種子及選題證據。
- 所有計分單位加總精確等於目標總分，且沒有 0 分單位。
- `score` 收據只證明精確題目已作答，不被用來判斷曾答錯。

### 測試

- 純函式測試涵蓋難易度百分比換算、配額分配、規則優先序、最大餘數配分、無解配分及穩定排序。
- 資料庫測試涵蓋單一科目限制、不可變發布版本、總分限制、外鍵、權限及冪等。
- 整合測試涵蓋同一設定的試組卷與發布一致、候選資料變動衝突、題數不足及 session 恢復。
- 隱私測試確認 `score` 不新增逐題對錯、答案、錯題佇列或相近題來源。
- 瀏覽器驗收涵蓋桌面及手機寬度、配額表編輯、缺口說明、配分預覽、發布及開始作答。
- 測試只使用隔離的合成帳號、學習者、題目及作答，不清除或覆蓋正式持久資料。

## 產品待確認事項

下列選項會改變資料與產品行為，施工前需要定案：

1. 「保留曾答錯」的預設語意要使用曾經錯過，還是最新結果仍錯。本文建議介面同時提供「曾答錯」與「目前錯題」，預設使用目前錯題。
2. `score` 收據是否計入「已作答」。本文建議計入，因為系統可證明該精確題目已送出，但不能知道對錯。
3. 收件者領取分享的模擬考後，是否重新依自己的歷史組卷。本文建議重新組卷，避免分享者歷史及固定試卷污染收件者結果。
4. 自動配分最小單位是否固定為 0.5 分。本文建議首階段固定 0.5 分，無解時要求調整，不自動產生 0 分題。
5. 多選題是否提供部分分數。本文建議首階段只有全對得分，之後以正式規則另行擴充。
6. 收藏清單及建立者是否納入首階段候選池。本文建議保留資料契約，但首階段介面先不顯示，降低組卷設定複雜度。
7. 是否開放非 100 分目標總分。本文建議資料模型支援正數目標總分，介面預設 100 分。
8. 是否開放既有 `instant` 或隱私型 `score` 作為模擬考揭露方式。本文建議首階段只開放 `complete`，先把交卷、配分及人工待評流程做完整。
9. 新建模擬考的預設難易度百分比。本文不先寫死比例，應由產品定案，之後集中保存於版本化設定，不散落在前端。

## 現況缺口

- 題庫已有科目、來源、標準題型、來源細題型、難易度、教材分類、知識點及來源專屬欄位，但現行練習 API 尚未支援完整多維伺服器組卷。
- 現有 `practice_plans` 已有動態／固定模式、題數、篩選快照及難度比例，但沒有題型乘難易度配額、歷史政策、固定總分及計分單位。
- 現有 session 可固定題目 revision 及可選小題，可作為固定試卷的執行基礎。
- `learner_question_stats`、`learner_part_stats` 及相近題統計已有 schema，但 runtime freshness 仍需確認或補齊。
- 題目模板及相近題關係只可使用 confirmed 資料。目前正式 confirmed 覆蓋不足時，介面應顯示此規則可用範圍有限，不得用未核准候選補足。
- 現有 `score` 是答對、答錯、待檢視及正確率的 session aggregate，不是具配分的考卷成績模型。
- 現有多格文字題只有答案格數量，尚無逐格答案及結果資料，不能直接完成逐格自動判分。
- `docs/PRODUCT_SPEC.md` 的部分現況文字仍把計畫／排程列為未完成，和已存在的學習本 migration 及交付紀錄不一致。正式施工前要先核對並同步修正，不可讓兩套狀態長期並存。
