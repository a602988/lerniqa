# 注音題目圖片辨識規格

## 適用範圍

本規格處理拍照、掃描圖片與掃描 PDF 中的國字注音題。目標是建立可校對的個人草稿。模型不得解題，也不得把推測結果當成原稿內容。

國字辨識與注音辨識使用不同的品質判斷。國字可讀不代表注音可靠；注音無法確認也不代表整題或整頁失敗。

## 字形與編碼依據

教育部《國語注音符號手冊》是字形、聲韻調與排印方式的依據。Unicode Bopomofo 區段 `U+3105` 至 `U+3129` 保存國語注音符號；聲調使用 `U+02C9`、`U+02CA`、`U+02C7`、`U+02CB` 與 `U+02D9`。延伸注音只在來源確實使用方言符號時接受。

- [教育部國語注音符號手冊](https://language.moe.gov.tw/001/Upload/files/site_content/M0001/juyin/html_ch/index.html)
- [Unicode Bopomofo 規格](https://unicode.org/versions/Unicode17.0.0/core-spec/chapter-18/)

通用繁體中文 OCR 可提供文字行位置與候選文字，但目前沒有已驗證的專案證據能證明它可可靠辨識各出版社、字體與掃描品質下的注音。因此 OCR 只供定位與候選比對。

## 輸出規則

模型必須保留原稿中的作答位置。來源為 `個性魯「ㄇㄤˇ」：` 時，草稿也要保存相同結構。模型不得補成 `個性魯莽`，不得加入原稿未印出的 `ㄌㄨˇ`，也不得把 `ㄇㄤˇ` 移到引號外。

每題只接受下列其中一種結果：

- 引號或括號內是純注音與聲調。
- 引號或括號內是原稿要求標注讀音的國字。
- 無法可靠抄錄時，以 `crop_ref` 保留該組注音的原圖。裁切替代文字為「待確認的注音原文」，寬度不得超過頁面 35%，高度不得超過頁面 15%。

模型輸出的注音必須在同頁 OCR 候選中找到完全相同的 Unicode 字串。OCR 沒有相同候選時，合法的注音字元仍不足以證明抄錄正確，系統要求模型改用 `crop_ref`。結果出現空白作答位置、日文假名、拉丁字母、國字與注音混在同一個作答位置，或注音離開原本作答位置時，系統同樣要求模型重新對照圖片。第二次仍不符合規則時，保留原始檔與既有草稿，回報辨識失敗。

本地模型輸出的 `crop_ref.ref` 不是可信任識別。系統在模型邊界依題目、作答區及內容位置重新建立整份結果內唯一的參照，再交由題目契約檢查；頁碼、來源、裁切座標與替代文字仍依模型結果嚴格驗證，不得因參照重複而放寬其他規則。

## 題數完整性

系統先從 OCR 行序擷取章節與題號，再把預期題號交給本地模型。題號可以接句點、頓號、括號、空格或直接接國字。OCR 把題號切成獨立一行時，該行仍算題號。章節前方只有空白括號或答案欄標記時，不得把章節誤判為共用素材題組。

章節標題明載「每題幾分，共幾分」時，系統以配分計算題數。標題使用「每字」時，至少要先辨識出兩個不同題號，才能用配分補足漏掉的題號。模型輸出的題號少於預期值時，整頁結果不會寫入草稿。系統要求模型重新輸出整頁；第二次仍漏題時，保留原始檔與既有草稿並回報分析失敗。

## 人工校對

草稿中的「待確認的注音原文」裁切必須維持在原本內容順序。使用者可以點選裁切圖放大查看，再依原稿輸入注音。原稿有 `「」`、`『』`、`（）` 或 `()` 時，可以連同外框輸入；外框必須成對。輸入含國字、拉丁字母、日文假名或其他符號時，不得替換裁切圖。

確認前保留裁切圖。確認後只把該裁切內容區塊替換成使用者輸入的文字，不修改前後題幹、答案、原始上傳檔或其他裁切圖。使用者無法確認時可以保留圖片並繼續校對其他題目。

## 圖片處理

模型同時接收完整校正頁與放大的文字行圖。完整頁保存版面與題號關係；放大圖只協助辨認小字注音。放大圖由 OCR 座標裁切，但內容仍以圖片為準。

影像強化只作用於送入模型的副本。原稿、校正頁與私人資產不可被放大、銳化或灰階結果覆寫。

## 驗收

測試要分開計算國字、注音符號與聲調。至少涵蓋不同字體、低解析度、透視歪斜、模糊、直式注音、橫式注音及相似字形。每個錯誤樣本要保存原圖授權狀態、人工標註、模型輸出與是否進入人工確認。

題數驗收要保留 OCR 的原始換行。測試至少涵蓋題號黏字、題號獨立成行、章節前方的版面雜訊，以及配分可推導題數的章節。只回傳一題的模型結果必須在寫入草稿前被拒絕。

沒有固定資料集與人工標註結果前，只能宣告流程與失敗保護已完成，不能宣告注音辨識準確率或市場級效果。
